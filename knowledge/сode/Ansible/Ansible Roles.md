# Структура Ansible-роли

Ansible-роль - это способ организации кода для автоматизации задач на серверах. Она представляет собой каталог с определённой структурой подкаталогов и файлов.
## Описание папок и файлов
```
/role
├── defaults
│ └── main.yml
├── files
│ ├── file1.txt
│ └── file2.conf
├── handlers
│ └── main.yml
├── meta
│ └── main.yml
├── tasks
│ └── main.yml
├── templates
│ └── config.j2
├── vars 
└── main.yml
```
*   **`defaults/`**
    *   **Описание:** Содержит переменные, значения которых будут использованы по умолчанию, если они не были заданы в другом месте (например, в инвентаре или playbook).
    *   **Файл:** `main.yml` (объявляются переменные по умолчанию).
    *   **Назначение:** Задание стандартных значений для параметров роли, которые могут быть переопределены пользователем.

*   **`files/`**
    *   **Описание:** Содержит статические файлы (например, скрипты, конфигурационные файлы), которые копируются на целевые серверы без изменений.
    *   **Примеры:** `file1.txt`, `file2.conf`.
    *   **Назначение:** Распространение неизменяемых файлов на серверы.

*   **`handlers/`**
    *   **Описание:** Содержит "обработчики" — задачи, которые выполняются только в случае, если были "вызваны" другими задачами (обычно для перезапуска сервисов после изменения конфигурации).
    *   **Файл:** `main.yml` (определение обработчиков).
    *   **Назначение:** Выполнение действий, зависящих от состояний других задач.

*   **`meta/`**
    *   **Описание:** Содержит метаданные роли (например, описание, зависимости, минимальные версии Ansible).
    *   **Файл:** `main.yml` (метаданные роли).
    *   **Назначение:** Описание роли, её зависимостей, и информации для пользователей Ansible.

*   **`tasks/`**
    *   **Описание:** Содержит основные задачи, выполняемые ролью.
    *   **Файл:** `main.yml` (определение основных задач).
    *   **Назначение:** Набор задач, которые нужно выполнить на сервере в рамках данной роли (установка ПО, настройка, развертывание).

*   **`templates/`**
    *   **Описание:** Содержит шаблоны конфигурационных файлов, которые могут содержать переменные. Эти переменные будут заменены фактическими значениями на целевом сервере.
    *   **Пример:** `config.j2` (Jinja2-шаблон).
    *   **Назначение:** Создание файлов конфигурации, изменяющихся в зависимости от переменных.

*   **`vars/`**
    *   **Описание:** Содержит переменные, которые переопределяют значения по умолчанию из `defaults/`.
    *   **Файл:** `main.yml` (переменные).
    *   **Назначение:** Задание переменных, которые имеют более высокий приоритет, чем значения по умолчанию.
