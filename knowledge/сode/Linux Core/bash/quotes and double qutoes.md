## Зачем использовать `[[ ]]` (двойные квадратные скобки) вместо `[ ]` (одинарных квадратных скобок) в Bash?

`[[ ]]` предоставляет расширенные и более безопасные возможности для проверки условий по сравнению с `[ ]` (команда `test`). Хотя оба используются для условных выражений, `[[ ]]` предлагает несколько преимуществ:

**1. Безопасность:**

*   **Предотвращает разбиение слов (word splitting):** `[[ ]]` не выполняет разбиение слов. Это означает, что вам не нужно заключать переменные в кавычки, чтобы предотвратить разделение строки на несколько слов, если она содержит пробелы.  Хотя, *рекомендуется* использовать кавычки для читаемости, даже с `[[ ]]`.

    ```bash
    VAR="some string with spaces"
    # [ $VAR == "some string with spaces" ]  # Сломается из-за word splitting
    [[ $VAR == "some string with spaces" ]] # Работает корректно
    ```

*   **Предотвращает раскрытие имен файлов (globbing/pathname expansion):**  `[[ ]]` не выполняет раскрытие имен файлов. Это означает, что специальные символы, такие как `*` и `?`, не будут интерпретироваться как подстановочные знаки для поиска файлов.

    ```bash
    FILE="*.txt"
    # [ -f $FILE ]  # Может привести к неожиданному результату, если есть файлы с расширением .txt
    [[ -f $FILE ]] # Работает корректно, проверяет, существует ли файл с именем "*.txt"
    ```

**2. Расширенные возможности:**

*   **Сопоставление с образцом (pattern matching):**  Оператор `==` внутри `[[ ]]` выполняет сопоставление с образцом, а не строгое равенство строк. Это позволяет использовать подстановочные знаки (wildcards) для сравнения строк.

    ```bash
    [[ "filename.txt" == *.txt ]] # Истинно, потому что *.txt является шаблоном
    [[ "filename.txt" == "filename.txt" ]] # Также истинно, простое сравнение строк
    ```

*   **Регулярные выражения:**  Оператор `=~` внутри `[[ ]]` позволяет сравнивать строки с использованием регулярных выражений.

    ```bash
    [[ "12345" =~ ^[0-9]+$ ]] # Истинно, потому что строка состоит только из цифр
    ```

*   **Логические операторы `&&` и `||`:** `[[ ]]` позволяет использовать `&&` (AND) и `||` (OR) непосредственно внутри скобок для комбинирования условий, что делает код более читаемым и компактным. С `[ ]` требуется более сложный синтаксис, с разделением на несколько команд.

    ```bash
    [[ -f file1 && -d dir1 ]] # Истинно, если file1 - файл, И dir1 - директория
    [[ -r file.txt || -w file.txt ]] # Истинно, если file.txt доступен для чтения ИЛИ для записи
    ```

**3. Улучшенная читаемость:**

*   Синтаксис `[[ ]]` более интуитивно понятен и упрощает чтение сложных условных выражений, особенно когда используются логические операторы и сопоставление с образцом.

**4. Отсутствие необходимости экранирования:**

*   Внутри `[[ ]]` не требуется экранировать многие специальные символы, которые необходимо экранировать внутри `[ ]`.

**5. Пример, демонстрирующий разницу:**

```bash
FILE="a b.txt"
if [ -f "$FILE" ]; then
    echo "Файл существует (одинарные скобки)"
fi

if [[ -f "$FILE" ]]; then
    echo "Файл существует (двойные скобки)"
fi

# Без кавычек:
if [ -f $FILE ]; then #Word splitting. Эквивалентно: if [ -f a b.txt ]; then
    echo "Файл существует (одинарные скобки, без кавычек)" #Не выдаст
fi

if [[ -f $FILE ]]; then #Не word splitting. FILE интерпретируется как единый аргумент.
    echo "Файл существует (двойные скобки, без кавычек)" #Выдаст, если есть файл "a b.txt"
fi
```

**6. Совместимость:**

`[[ ]]` является расширением Bash и не является частью стандарта POSIX.  Это означает, что код, использующий `[[ ]]`, может быть несовместим с другими оболочками, такими как `sh`.  Если важна переносимость скрипта между разными оболочками, следует придерживаться `[ ]` и POSIX-совместимого синтаксиса.  Однако, в большинстве современных систем используется Bash как оболочка по умолчанию, поэтому в этих случаях использование `[[ ]]` обычно не является проблемой.

**Когда использовать `[ ]`?**

*   Когда требуется максимальная переносимость скрипта на другие оболочки, не поддерживающие `[[ ]]`.
*   В очень простых условиях, когда не требуются расширенные возможности и безопасность `[[ ]]`.

**Вывод:**

В большинстве случаев, особенно при написании скриптов для Bash, **рекомендуется использовать `[[ ]]` вместо `[ ]`**.  Это повышает безопасность, упрощает написание сложных условий и делает код более читаемым.  Переносимость может быть проблемой, но в современных окружениях, где используется Bash, это обычно не является критическим фактором.
