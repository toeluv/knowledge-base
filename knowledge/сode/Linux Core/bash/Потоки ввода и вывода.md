В Linux/Unix все команды работают с тремя стандартными потоками данных:

stdin (0) — стандартный ввод (данные, которые программа читает, например, с клавиатуры).

stdout (1) — стандартный вывод (нормальные результаты работы команды).

stderr (2) — стандартный поток ошибок (сообщения об ошибках).

`>, <` - перенаправление потоков в файл, команду и из

```bash
cat 1.txt > 2.txt
grep help < 2.txt
```

`>>, <<` - перенаправление потоков в файл, команду и из (с добавлением текста, а не заменой)

```bash
cat 1.txt >> 2.txt
grep help << 2.txt
```

`|` - перенаправление результата команды в другую команду

```bash
cat 1.txt | grep ok
```

`&&` - выполнение другой команды, если предыдущая завершена успешно

```bash
ls -a && echo "Success"
```

`||` - выполнение другой команды, если предыдущая завершена неуспешно

```bash
cd /root || echo "Error"
```
---

### Разница между `;`, `&&`, `||`**
| Оператор | Действие | Пример |
|----------|----------|--------|
| `;`  | Выполняет команды **последовательно** | `cmd1; cmd2` → выполнятся обе |
| `&&` | Выполняет `cmd2` **только если `cmd1` успешна** | `mkdir dir && cd dir` |
| `||` | Выполняет `cmd2` **только если `cmd1` провалилась** | `ping host || echo "Ошибка"` |

---

### Пайпы (`|`) 

Пайпы (pipes) позволяют передавать вывод одной команды на вход другой.

#### Основные принципы:
- `|` - передает стандартный вывод (stdout) слева на стандартный ввод (stdin) справа
- `|&` - передает и stdout, и stderr (в bash)
- Цепочки могут быть любой длины: `cmd1 | cmd2 | cmd3 ...`
#### Типовые сценарии:
1. **Фильтрация вывода**  
   `dmesg | grep "error"`

2. **Постраничный просмотр**  
   `ls -la /etc | less`

3. **Обработка данных**  
   `cat access.log | cut -d' ' -f1 | sort | uniq -c`

4. **Сохранение с просмотром**  
   `sudo tcpdump -i eth0 | tee packet_capture.log`

5. **Передача между сложными командами**  
   `ffmpeg -i input.mp4 2>&1 | grep "Duration"`

#### Особенности:
- Пайпы работают в памяти, не создавая временных файлов
- Команды выполняются параллельно (не ждут завершения предыдущей)
- Если правая команда завершится с ошибкой, левая продолжит работу

#### Примеры с обработкой ошибок:
```bash
# Игнорировать ошибки в первой команде
cmd_may_fail 2>/dev/null | cmd2

# Передать ошибки дальше
cmd_may_fail |& grep "pattern"
```

#### Комбинирование с перенаправлением:

```bash
# Сохранить вывод и передать дальше
make | tee build.log | grep "warning"

# Разделить потоки
cmd 2>errors.log | tee output.log >/dev/null
```
## Работа с ошибками

#### Разделение потоков
```bash
cat /etc/hosts /nonexistent 1>>success.log 2>>errors.log
```
#### Перенаправление ошибок (2>)

```bash
command 2>errors.log
```
#### Добавление ошибок (2>>)

```bash
command 2>>errors.log
```

#### Объединение потоков (2>&1)
```bash
command > output.txt 2>&1  # Важен порядок!
command &> output.txt
```
#### Специальные файлы

`/dev/null` - "черная дыра" для ненужного вывода

```bash
command > /dev/null
```
