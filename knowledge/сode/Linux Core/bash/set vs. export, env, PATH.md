## Разница между `set` и `export` в Bash

Обе команды, `set` и `export`, используются для управления окружением оболочки Bash, но выполняют разные функции:

**1. `set` - Управление опциями оболочки**

*   **Функция:**  `set` используется для установки или изменения опций (настроек) самой оболочки Bash. Эти опции влияют на поведение оболочки, например, как она обрабатывает ошибки, как интерпретирует команды и как отображает вывод.
*   **Область действия:**  Опции, установленные с помощью `set`, действуют только в текущем процессе оболочки и всех его дочерних процессах. Они не влияют на глобальное окружение системы.
*   **Примеры:**
    *   `set -x`:  Включает режим трассировки.  Оболочка выводит команды перед их выполнением, полезно для отладки скриптов.
    *   `set -e`:  Устанавливает режим "exit on error".  Если какая-либо команда завершается с ненулевым кодом завершения (ошибкой), скрипт немедленно завершает выполнение.
    *   `set +x`:  Отключает режим трассировки.
    *   `set -u`:  Если используется в скрипте, при попытке использовать неопределенную переменную произойдет ошибка.
    *   `set -o errexit`: Тоже самое, что `set -e`.
    *   `set -o nounset`: Тоже самое, что `set -u`.
    *   `set --`:  Сбрасывает все позиционные параметры `$1`, `$2`, и т.д.

*   **Важно:** `set` обычно используется в скриптах для настройки поведения оболочки в рамках этого скрипта.  Не следует путать с установкой переменных окружения (см. `export`).

**2. `export` - Установка и экспорт переменных окружения**

*   **Функция:** `export` используется для объявления переменных окружения. Переменные окружения содержат информацию, доступную для всех процессов, запущенных оболочкой (и её дочерних процессов).  Они служат для передачи настроек и данных между процессами.
*   **Область действия:** Переменные, экспортированные с помощью `export`, становятся доступны для всех дочерних процессов текущей оболочки, а также сохраняются в рамках текущей сессии (до её завершения или перезагрузки).  Они не влияют на родительский процесс, запустивший оболочку.  Для постоянного сохранения переменной, ее нужно добавить в файл конфигурации оболочки (например, `~/.bashrc`).
*   **Примеры:**
    *   `export MY_VAR="значение"`:  Устанавливает переменную окружения `MY_VAR` и экспортирует ее. Теперь эта переменная будет доступна в дочерних процессах.
    *   `export PATH="$PATH:/путь/к/вашей/команде"`:  Добавляет новый путь к переменной `PATH`, позволяя оболочке находить исполняемые файлы в этой директории.
    *   `export EDITOR=vim`:  Устанавливает редактор по умолчанию.  Программы, использующие переменную `EDITOR`, будут знать, какой редактор использовать.
    *   `MY_VAR="значение"`; export MY_VAR:  Тоже самое, что и `export MY_VAR="значение"`, но более разделенный процесс - сначала устанавливается локальная переменная, потом экспортируется.
*   **Важно:**  `export` используется для настройки среды выполнения, передачи информации между процессами и управления поведением программ.  Переменные окружения могут быть использованы в скриптах и командах для настройки их работы.

**Сводка:**

| Особенность       | `set`                                          | `export`                                       |
| ----------------- | ----------------------------------------------- | ----------------------------------------------- |
| **Функция**       | Управление опциями оболочки                  | Установка и экспорт переменных окружения     |
| **Область действия** | Текущая оболочка и её дочерние процессы         | Текущая оболочка и её дочерние процессы        |
| **Влияние**        | Изменяет поведение оболочки (например, отладка) | Предоставляет информацию другим процессам     |
| **Примеры**        | `set -x`, `set -e`, `set --`                | `export PATH`, `export EDITOR`, `export MY_VAR` |
| **Типичное использование** | В скриптах, для настройки поведения скрипта. | В скриптах и в интерактивных сессиях, для настройки окружения, передачи параметров |

**Ключевое различие:**  `set` влияет на поведение оболочки, а `export` - на доступность информации для других процессов. `set` скорее про конфигурацию оболочки, а `export` - про среду выполнения и передачу данных.

## `PATH`: Путь поиска исполняемых файлов

`PATH` – это одна из самых важных переменных окружения в Bash. Она содержит список директорий, в которых оболочка будет искать исполняемые файлы (команды, скрипты, программы), когда вы вводите команду в терминале.

**1. Что такое `PATH`?**

*   `PATH` – это переменная окружения, которая содержит список путей к директориям, разделенных двоеточиями (`:`).
*   Когда вы вводите команду (например, `ls` или `gcc`), оболочка Bash просматривает директории, указанные в `PATH`, в порядке их перечисления, в поисках файла с таким же именем.
*   Если файл найден, оболочка выполняет его. Если нет, вы получите ошибку "command not found".

**2. Зачем нужен `PATH`?**

*   **Удобство:** Позволяет запускать команды, просто набрав их имя, без указания полного пути (например, `ls` вместо `/bin/ls`).
*   **Гибкость:**  Дает возможность добавлять свои директории с пользовательскими скриптами и утилитами, делая их доступными из любого места в системе.
*   **Организация:**  Помогает структурировать файловую систему, размещая исполняемые файлы в определенных директориях, а не разбрасывая их по всей системе.

**3. Как посмотреть значение `PATH`?**

Чтобы увидеть текущее значение переменной `PATH`, выполните в терминале команду:

```bash
echo $PATH
```

Вывод будет представлять собой строку, содержащую список путей, разделенных двоеточиями.  Пример:

```
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
```

**4. Как изменить `PATH`?**

Изменение `PATH` происходит путем изменения значения переменной окружения `PATH`.  Есть несколько способов:

*   **Временно (только для текущей сессии):**

    ```bash
    export PATH="$PATH:/путь/к/вашей/директории"
    ```

    *   `$PATH` в этой команде ссылается на текущее значение `PATH`.
    *   `:/путь/к/вашей/директории` добавляет новый путь в конец списка (рекомендуемый способ).
    *   Порядок имеет значение! Оболочка ищет в директориях в порядке слева направо.  Если добавить свой путь в начало списка, ваши версии команд будут приоритетнее системных (но это может быть опасно, если вы не уверены в своих изменениях).

*   **Постоянно (для всех новых сессий):**

    Для постоянного изменения `PATH`, необходимо отредактировать файл конфигурации вашей оболочки.  Чаще всего это:

    *   `~/.bashrc` (для Bash)
    *   `~/.zshrc` (для Zsh)
    *   `~/.profile` или `~/.bash_profile` (для Bash при входе в систему)

    Добавьте в этот файл строку, аналогичную вышеприведенной, с добавлением пути к вашей директории.  Например:

    ```bash
    export PATH="$PATH:$HOME/bin"  # Добавляем директорию bin в вашей домашней директории
    ```

    После сохранения изменений, необходимо перезапустить терминал или выполнить `source ~/.bashrc` (или соответствующий файл конфигурации), чтобы изменения вступили в силу.

*   **Рекомендации по добавлению путей:**
    *   Добавляйте свои пути в *конец* списка `PATH`, чтобы сохранить приоритет системных команд.
    *   Создайте в своей домашней директории папку `bin` (`mkdir ~/bin`) для хранения личных скриптов и утилит.  Добавьте  `$HOME/bin` в `PATH`.
    *   Для каждой программы, которую вы хотите установить, прочитайте документацию, где указано, какие пути и переменные окружения необходимо настроить.
    *   Помните, что изменения в файлах конфигурации применяются только к новым сессиям или после выполнения `source`.

**5. Как работает поиск команд?**

Когда вы вводите команду, Bash выполняет следующие шаги:

1.  **Встроенные команды:** Сначала Bash проверяет, является ли команда встроенной (например, `cd`, `echo`, `export`). Если да, выполняется встроенная команда.
2.  **Псевдонимы (aliases):** Проверяется наличие псевдонима с таким именем. Если псевдоним найден, вместо него выполняется соответствующая команда.
3.  **Поиск в `PATH`:**  Если это не встроенная команда и нет псевдонима, Bash просматривает директории, указанные в `PATH`, в порядке следования, и ищет исполняемый файл с таким именем.
4.  **Выполнение:** Если файл найден, он выполняется.
5.  **Ошибка "command not found":** Если файл не найден ни в одной из директорий `PATH`, вы получаете ошибку "command not found".

**6. Безопасность:**

*   Будьте осторожны при добавлении путей в `PATH`, особенно если они включают непроверенные или ненадежные директории.  Злоумышленники могут подменить системные команды своими, если их директория окажется раньше в `PATH`.
*   Не рекомендуется добавлять `.` (текущую директорию) в `PATH`, особенно в общих системах. Это может привести к неожиданному выполнению файлов из текущей директории.

**В заключение:**

`PATH` – это краеугольный камень удобства и гибкости в Bash. Правильная настройка `PATH` позволяет эффективно использовать командную строку, запускать программы и управлять своим окружением. Понимание того, как работает `PATH`, является необходимым навыком для любого пользователя Bash.
