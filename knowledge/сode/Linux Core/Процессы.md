### Что такое процесс?

*   **Определение:**  Экземпляр запущенной программы. Включает в себя код программы, данные, ресурсы (открытые файлы, сокеты и т.д.) и контекст выполнения (значения регистров, стек вызовов и т.д.).
*   **Программа vs. Процесс:** Программа - это статический набор инструкций (файл). Процесс - это динамическое исполнение этих инструкций. Одна программа может иметь много процессов.
### Важное
`ctrl + C` - завершает процесс
`ctrl + Z` - только останавливает процесс, чтобы выйти - `exit` 2 раза или перевести на задний фон `bg %1`
### Иерархия процессов

*   **Дерево процессов:**  Все процессы в Linux организованы в иерархическое дерево, где каждый процесс (кроме init) имеет родительский процесс.
*   **init (PID 1):**  Первый процесс, запущенный ядром при загрузке системы.  Является предком всех остальных процессов.  Отвечает за запуск системных служб и управление процессом загрузки.
*   **Родительский процесс:**  Процесс, создавший другой процесс.
*   **Дочерний процесс:** Процесс, созданный другим процессом.
*   **Приоритет** - Изменяется от -20 до 19.

### PID (Process ID)

*   Уникальный числовой идентификатор, присваиваемый каждому процессу ядром.
*   Используется для идентификации процесса при управлении процессами (например, при отправке сигналов).

### PPID (Parent Process ID)

*   ID родительского процесса.

### Состояния процессов

*   **Running (R):**  Процесс выполняется или готов к выполнению на CPU.
*   **Sleeping (S):**  Процесс ожидает завершения события (например, ввод/вывод).  Может быть прерываемым (interruptible) или непрерываемым (uninterruptible).
*   **Stopped (T):**  Процесс остановлен (например, сигналом SIGSTOP). Может быть возобновлен сигналом SIGCONT.
*   **Zombie (Z):** Процесс завершился, но его запись еще не была удалена из таблицы процессов.  Это делается для того, чтобы родительский процесс мог получить информацию о завершении дочернего процесса (код возврата, и т.д.). Zombie процессы потребляют ресурсы системы.
*   **Disk Sleep (D):** Непрерываемый сон, обычно во время операций ввода-вывода на диск.  Нельзя убить обычным способом.
У букв могут быть теги
*   **<, >** - high, low priority (not nice to other users)
*   **N** - low priority (nice to other users)
*   **L** - has pages locked into memory (for real time)
*   **s** - is a session leader
*   **l** - multithreading
*   **+** - in foreground proccess group

### Управление процессами: Команды

*   **ps:**  Вывод информации о процессах.
    *   `ps aux`:  Вывод информации обо всех процессах, запущенных всеми пользователями, с подробной информацией.
    *   `ps -ef`:  Альтернативный способ вывода информации обо всех процессах.
    *   `ps -x`: Статус, TTY процесса.
    *   `ps -u root`: Посмотреть процессы конкретного пользователя.
    *   `ps -p <PID>`: Вывод информации о процессе с указанным PID.
*   **top:**  Динамический мониторинг процессов в реальном времени, показывающий использование CPU, памяти и т.д.
*   **htop:**  Интерактивный монитор процессов, более удобный, чем `top`.  (Нужно установить отдельно).
*   **kill:**  Отправка сигналов процессам.
    *   `kill <PID>`: Отправка сигнала SIGTERM (по умолчанию).  Просит процесс завершиться "вежливо".
    *   `kill -9 <PID>` или `kill -SIGKILL <PID>`:  Отправка сигнала SIGKILL.  Завершает процесс немедленно (невозможно игнорировать). Использовать с осторожностью.
*   **killall:**  Завершение всех процессов с указанным именем.
    *   `killall <имя_процесса>`
*   **pkill:** Завершение процессов по имени или другим критериям (например, по пользователю).
    *   `pkill <имя_процесса>`
*   **bg:** Перевод остановленного процесса в фоновый режим.
*   **fg:** Перевод фонового процесса в активный режим (на передний план).
      ```bash
      sleep 1000 &
      jobs
      fg &1
      ```
*   **jobs:** Список фоновых процессов.
*   **nice:** Запуск процесса с указанным приоритетом (renice для изменения приоритета существующего процесса).
    *   `nice -n <значение_приоритета> <команда>`. Пример:
    *   ```bash
        $ nice -n 11 vim hello.txt
        $ renice -n 3 -p 603 # изменить приоритет
        ```

### Сигналы

*   **Определение:** Способ взаимодействия между процессами.  Один процесс может отправлять сигналы другому процессу, чтобы уведомить его о событии или запросить выполнение действия.
*   **Примеры:**
    *   `SIGTERM (15)`: Запрос на завершение процесса (по умолчанию для `kill`).
    *   `SIGKILL (9)`:  Немедленное завершение процесса.
    *   `SIGSTOP (19)`: Остановка процесса.
    *   `SIGCONT (18)`: Возобновление остановленного процесса.
    *   `SIGINT (2)`: Прерывание процесса (обычно вызывается нажатием Ctrl+C).
    *   `SIGHUP (1)`:  Hangup (разрыв соединения). Часто используется для перезапуска процесса.

### Запуск процессов

*   **Командная строка:**  Простое выполнение команды.
*   **Фоновый режим (&):** Запуск процесса в фоновом режиме.  Например, `command &`.
*   **nohup:**  Запуск команды, игнорирующей сигнал SIGHUP.  Полезно для длительных процессов, которые не должны завершаться при закрытии терминала.
    *   `nohup command &`
*   **systemd:**  Используется для управления системными службами.  Создание unit-файлов для автоматического запуска и управления процессами.

### Fork, Exec

*   **fork():**  Системный вызов, создающий новый процесс (дочерний) путем копирования родительского процесса. Дочерний процесс получает собственное пространство памяти (copy-on-write).
*   **exec():**  Семейство системных вызовов, заменяющих текущий процесс (код и данные) новым процессом, указанным в аргументах.

**Типичный сценарий:**

1.  Родительский процесс вызывает `fork()`.
2.  Дочерний процесс (получивший копию родительского) вызывает `exec()` для запуска другой программы.
3.  Родительский процесс продолжает свое выполнение (может ожидать завершения дочернего).

### Zombies и Orphans

*   **Zombie Process:** Процесс, завершившийся, но его информация еще не собрана родительским процессом.  Если родительский процесс не вызывает `wait()` (или аналогичную функцию) для сбора информации, процесс остается в состоянии zombie.
*   **Orphan Process:** Процесс, родительский процесс которого завершился до него.  Процесс `init` автоматически становится родителем для всех процессов-сирот.

### Ресурсы процессов

*   **CPU Time:** Время, затраченное процессом на выполнение кода.
*   **Memory:** Использование памяти (RAM, swap).
*   **I/O:** Ввод/вывод (чтение/запись данных).
*   **Open Files:** Количество открытых файлов и сокетов.
*   **Threads:** Количество потоков (легковесных процессов) в процессе.

### Инструменты мониторинга ресурсов

*   `top`, `htop`: Общий мониторинг.
*   `vmstat`: Мониторинг виртуальной памяти.
*   `iostat`: Мониторинг ввода/вывода.
*   `free`: Отображение использования памяти.
*   `lsof`: Вывод списка открытых файлов.

### Важные файлы

*   `/proc/<PID>`: Каталог, содержащий информацию о процессе с указанным PID.
*   `/var/log/syslog`: Системный журнал, содержащий сообщения о системных событиях и ошибках, связанных с процессами.

### Вывод

Понимание процессов является основой для администрирования Linux и отладки приложений. Использование команд управления процессами и мониторинга ресурсов поможет эффективно управлять системой и решать проблемы.
