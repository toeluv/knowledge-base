### **Папка `/run` в Linux: временные файлы процессов и рантайм-данные**

Папка `/run` (ранее также `/var/run`) — это временное файловое хранилище, создаваемое при загрузке системы и используемое для хранения:
- **PID-файлов** (идентификаторов процессов),
- **сокетов** (например, `/run/docker.sock`),
- **lock-файлов** (файлов блокировок),
- **временных данных демонов** (systemd, udev, dbus и др.).

---

## **1. Назначение `/run`**
- **Временные файлы процессов**  
  Многие демоны (например, `sshd`, `nginx`, `docker`) создают здесь свои PID-файлы (например, `/run/nginx.pid`).  
- **Коммуникационные сокеты**  
  Некоторые сервисы (Docker, D-Bus) используют Unix-сокеты в `/run` для межпроцессного взаимодействия.  
- **Хранение состояния системы**  
  Например, `systemd` хранит здесь свои runtime-данные (`/run/systemd/`).  
- **Быстрый доступ**  
  Поскольку `/run` обычно размещается в **RAM** (tmpfs), доступ к файлам очень быстрый.  

---

## **2. Структура `/run`**
| Файл/Папка             | Описание |
|------------------------|----------|
| `/run/lock/`           | Lock-файлы (аналог `/var/lock`) |
| `/run/user/<UID>/`     | Runtime-данные пользовательских сеансов (например, `pulseaudio`, `systemd --user`) |
| `/run/docker.sock`     | Сокет Docker API |
| `/run/sshd.pid`        | PID-файл демона SSH |
| `/run/systemd/`        | Временные данные systemd |
| `/run/udev/`           | Данные udev (управление устройствами) |
| `/run/cups/`           | Временные файлы CUPS (печать) |

---

## **3. Особенности**
### **1. Размещение в оперативной памяти (tmpfs)**
- `/run` монтируется как **tmpfs** (в RAM), поэтому:
  - Файлы исчезают после перезагрузки.
  - Нет нагрузки на диск (высокая скорость доступа).
- Проверить можно так:
  ```bash
  mount | grep run
  ```
  Вывод:
  ```bash
  tmpfs on /run type tmpfs (rw,nosuid,nodev,relatime)
  ```

### **2. Совместимость с `/var/run`**
- В современных дистрибутивах `/var/run` — это **симлинк** на `/run`:
  ```bash
  ls -l /var/run
  ```
  Вывод:
  ```bash
  lrwxrwxrwx 1 root root 4 May 10 00:00 /var/run -> /run
  ```

### **3. Права доступа**
- Обычно владелец — `root:root`, но некоторые подпапки (например, `/run/user/<UID>/`) принадлежат пользователям.  
- Пример:
  ```bash
  drwx------ 5 user user 120 May 10 12:00 /run/user/1000/
  ```

---

## **4. Примеры использования**
### **1. Проверка PID-файла демона**
```bash
cat /run/nginx.pid  # Узнать PID процесса nginx
```

### **2. Взаимодействие через сокет (Docker)**
```bash
curl --unix-socket /run/docker.sock http://localhost/containers/json
```

### **3. Очистка lock-файлов**
Если программа завершилась некорректно, можно удалить её lock-файл:
```bash
sudo rm /run/lock/nginx.lock
```

---

## **5. Отличие от других временных папок**
| Папка       | Назначение | Сохраняется после перезагрузки? |
|-------------|------------|----------------------------------|
| `/run`      | PID-файлы, сокеты, runtime-данные | ❌ Нет |
| `/tmp`      | Временные файлы программ | ❌ Нет (обычно очищается) |
| `/var/tmp`  | Временные файлы, которые должны сохраняться | ✅ Да |
| `/dev/shm`  | Shared memory (аналог tmpfs) | ❌ Нет |

---

## **6. Проблемы и решения**
### **1. "No space left on device"**
Если `/run` заполнится (из-за большого количества временных файлов):
```bash
df -h /run  # Проверить свободное место
```
**Решение:**  
- Увеличить размер tmpfs (в `/etc/fstab`):
  ```bash
  tmpfs /run tmpfs rw,size=100M 0 0
  ```
- Перезагрузить систему или перемонтировать:
  ```bash
  sudo mount -o remount,size=200M /run
  ```

### **2. Отсутствие PID-файла**
Если демон не создаёт PID-файл (например, `/run/sshd.pid`), это может означать, что он не запущен или завершился с ошибкой.

**Решение:**  
```bash
sudo systemctl restart sshd  # Перезапустить сервис
```

---

## **Вывод**
- `/run` — это **временное хранилище** для PID-файлов, сокетов и runtime-данных.  
- Размещается в **RAM** (tmpfs), поэтому файлы **не сохраняются** после перезагрузки.  
- Критически важна для работы **демонов** (systemd, Docker, udev).  
- Аналог `/var/run` (в современных системах это симлинк).  

Если какая-то служба не запускается, проверьте `/run` на наличие её PID-файла или сокета!
