### **Инкрементальные бэкапы в Linux**  

Инкрементальные бэкапы сохраняют только изменения с момента последнего резервного копирования, что экономит место и время.  

---

## **1. Основные принципы**  
- **Полный бэкап (Full Backup)** – сохраняет все данные.  
- **Инкрементальный бэкап (Incremental Backup)** – сохраняет только изменения с последнего бэкапа (полного или инкрементального).  
- **Дифференциальный бэкап (Differential Backup)** – сохраняет изменения с момента последнего **полного** бэкапа.  

**Преимущества инкрементальных бэкапов:**  
- Меньший объем данных.  
- Быстрое создание.  
- Экономия дискового пространства.  

**Недостатки:**  
- Восстановление сложнее (нужна цепочка бэкапов).  
- Риск потери данных при повреждении одного звена цепочки.  

---

## **2. Инструменты для инкрементальных бэкапов**  

### **2.1. `tar` с ключом `-g` (создание меток изменений)**  

#### **Создание полного бэкапа**  
```bash
tar -czg /backup/snapshot.snar -f /backup/full_backup_$(date +%Y%m%d).tar.gz /home/user
```
- `-g /backup/snapshot.snar` – файл с метками изменений (хранит состояние файлов).  
- `-f` – имя архива.  

#### **Создание инкрементального бэкапа**  
```bash
tar -czg /backup/snapshot.snar -f /backup/inc_backup_$(date +%Y%m%d).tar.gz /home/user
```
- Использует **тот же файл `snapshot.snar`**, чтобы определить изменения.  

#### **Восстановление данных**  
1. Сначала распаковываем **полный бэкап**:  
   ```bash
   tar -xzg -f /backup/full_backup_20240501.tar.gz -C /restore
   ```
2. Затем **инкрементальные бэкапы по порядку**:  
   ```bash
   tar -xzg -f /backup/inc_backup_20240502.tar.gz -C /restore
   tar -xzg -f /backup/inc_backup_20240503.tar.gz -C /restore
   ```

#### **Автоматизация через скрипт**  
```bash
#!/bin/bash

BACKUP_DIR="/backup"
SOURCE_DIR="/home/user"
SNAPSHOT_FILE="$BACKUP_DIR/snapshot.snar"
DATE=$(date +%Y%m%d)

# Полный бэкап (раз в неделю)
if [ $(date +%u) -eq 1 ]; then  # Если понедельник
    tar -czg "$SNAPSHOT_FILE" -f "$BACKUP_DIR/full_backup_$DATE.tar.gz" "$SOURCE_DIR"
else
    # Инкрементальный бэкап
    tar -czg "$SNAPSHOT_FILE" -f "$BACKUP_DIR/inc_backup_$DATE.tar.gz" "$SOURCE_DIR"
fi
```

---

### **2.2. `rsync` + `hardlinks` (альтернативный метод)**  
```bash
rsync -a --link-dest=/backup/full_backup /home/user /backup/inc_backup_$(date +%Y%m%d)
```
- `--link-dest` – создает жесткие ссылки на неизмененные файлы.  

---

### **2.3. `rdiff-backup` (дельта-копирование)**  
```bash
rdiff-backup /home/user /backup/user
```
- Автоматически управляет инкрементами.  
- Восстановление на любую дату:  
  ```bash
  rdiff-backup -r 7D /backup/user /home/user_restored
  ```

---

### **2.4. `BorgBackup` (шифрование + дедупликация)**  
```bash
borg create /backup/repo::backup-{now} /home/user
borg list /backup/repo
borg extract /backup/repo::backup-2024-05-27
```

---

## **3. Автоматизация через `cron`**  
```bash
0 2 * * 1 /path/to/full_backup.sh  # Полный бэкап в понедельник
0 2 * * 2-7 /path/to/inc_backup.sh  # Инкрементальный со вторника по воскресенье
```

---

## **4. Восстановление данных из `tar -g`**  
1. **Распаковываем полный бэкап**:  
   ```bash
   tar -xzf full_backup_20240501.tar.gz -C /restore
   ```
2. **Применяем инкрементальные архивы по порядку**:  
   ```bash
   tar -xzg -f inc_backup_20240502.tar.gz -C /restore --keep-newer-files
   ```

---

## **5. Лучшие практики**  
- **Храните `snapshot.snar` в надежном месте** (без него восстановление сложнее).  
- **Проверяйте бэкапы** (`tar -tzf archive.tar.gz`).  
- **Шифруйте敏感数据** (`gpg -c archive.tar.gz`).  
- **Тестируйте восстановление** перед реальной необходимостью.  

---

## **Итог**  
| Метод             | Плюсы                              | Минусы                     |  
|-------------------|------------------------------------|----------------------------|  
| **`tar -g`**      | Простота, работает везде           | Ручное управление цепочками |  
| **`rsync`**       | Быстро, экономит место             | Нет истории версий          |  
| **`rdiff-backup`**| Автоматические дельты              | Менее популярен            |  
| **`BorgBackup`**  | Шифрование + дедупликация          | Сложнее настройка          |  

**Выбор зависит от:**  
- Объема данных.  
- Требований к безопасности.  
- Частоты бэкапов.
