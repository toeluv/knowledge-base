### **Конспект: Настройка прав sudo через `visudo`**  

---

## **1. Основы `visudo`**  
**`visudo`** — утилита для безопасного редактирования `/etc/sudoers`.  

🔹 **Зачем использовать `visudo`, а не прямой редактор?**  
- Проверяет синтаксис перед сохранением.  
- Блокирует файл от одновременного редактирования.  
- Предотвращает ошибки, которые могут **заблокировать доступ к sudo**.  

```bash
sudo visudo  # открывает файл в редакторе (nano/vi)
```

---

## **2. Формат правил в `/etc/sudoers`**  
Общий синтаксис:  
```
пользователь хост=(пользователь:группа) команды
```

### **Примеры полных прав**  
#### **① Классический вариант (без управления группой)**  
```bash
%admin ALL=(ALL) ALL
```
- Позволяет выполнять **любые команды от любого пользователя**, но без смены группы.  
- Пример использования:  
  ```bash
  sudo -u postgres psql  # OK
  sudo -u postgres -g postgres psql  # Ошибка (группа не указана в правилах)
  ```

#### **② Современный вариант (с управлением группой)**  
```bash
%sudo ALL=(ALL:ALL) ALL
```
- Позволяет выполнять команды **от любого пользователя и с любой группой**.  
- Пример:  
  ```bash
  sudo -u postgres -g postgres psql  # OK
  ```
- **Стандарт в Ubuntu/Debian**.

---

## **3. Примеры НЕПОЛНЫХ (ограниченных) прав**  

### **① Разрешить только определённые команды**  
```bash
user1 ALL=(root) /usr/bin/apt, /usr/bin/systemctl
```
- **Что можно:**  
  ```bash
  sudo apt update        # OK
  sudo systemctl restart nginx  # OK
  ```
- **Что нельзя:**  
  ```bash
  sudo su               # Запрещено (не в списке разрешённых команд)
  sudo rm -rf /         # Запрещено
  ```

### **② Разрешить команды только для конкретного пользователя (не root)**  
```bash
user2 ALL=(postgres) /usr/bin/psql
```
- **Что можно:**  
  ```bash
  sudo -u postgres psql  # OK
  ```
- **Что нельзя:**  
  ```bash
  sudo -u root bash      # Запрещено (только postgres)
  sudo apt update        # Запрещено (нет в списке)
  ```

### **③ Разрешить команды без пароля (`NOPASSWD`)**  
```bash
user3 ALL=(ALL) NOPASSWD: /usr/bin/apt
```
- **Что можно:**  
  ```bash
  sudo apt update  # Работает без пароля
  ```
- **Что нельзя:**  
  ```bash
  sudo su          # Требует пароль (не в NOPASSWD)
  ```

### **④ Разрешить только чтение логов**  
```bash
user4 ALL=(ALL) /usr/bin/cat /var/log/*
```
- **Что можно:**  
  ```bash
  sudo cat /var/log/nginx/error.log  # OK
  ```
- **Что нельзя:**  
  ```bash
  sudo cat /etc/shadow  # Запрещено (не в /var/log/)
  sudo vim /var/log/nginx/access.log  # Запрещено (только cat)
  ```

---

## **4. Опасные примеры (как НЕ надо делать)**  

### **❌ Слишком широкие права**  
```bash
user5 ALL=(ALL) NOPASSWD: ALL
```
- **Чем опасно?**  
  - Пользователь может делать **что угодно без пароля** (`sudo rm -rf /`, `sudo su` и т. д.).  

### **❌ Разрешение shell-команд без ограничений**  
```bash
user6 ALL=(ALL) /bin/bash, /bin/sh
```
- **Чем опасно?**  
  - Фактически даёт **полный доступ** через `sudo bash`.  

---

## **5. Проверка своих прав sudo**  
```bash
sudo -l
```
Вывод:  
```
User user1 may run the following commands on host:
    (root) /usr/bin/apt, /usr/bin/systemctl
```

---

## **Итог**  
✅ **Правильно:**  
- Использовать `visudo` для редактирования.  
- Давать **минимально необходимые** права.  
- В Ubuntu/Debian использовать группу `%sudo`.  

❌ **Неправильно:**  
- Давать `ALL=(ALL) ALL` без необходимости.  
- Разрешать `NOPASSWD` для опасных команд.  

📌 **Совет:**  
- Для сложных правил используйте `/etc/sudoers.d/`:  
  ```bash
  sudo visudo -f /etc/sudoers.d/custom_rules
  ```
