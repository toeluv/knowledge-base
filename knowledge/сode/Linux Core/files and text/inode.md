## **Inode в Linux/Unix: что это и зачем нужно?**  

**Inode** (Index Node) — это структура данных в файловых системах Unix/Linux, которая хранит **метаданные файла** (всё, кроме имени и содержимого).  

---

## **1. Что хранится в inode?**  
Каждый файл и директория имеет уникальный inode, содержащий:  
- **Тип файла** (обычный файл, директория, символьная ссылка, устройство и т. д.).  
- **Права доступа** (`chmod`, `rwx` для владельца/группы/остальных).  
- **UID и GID** (владелец и группа).  
- **Размер файла** (в байтах).  
- **Временные метки** (время создания, модификации, доступа — `atime`, `mtime`, `ctime`).  
- **Ссылки на блоки данных** (где физически лежит содержимое файла на диске).  
- **Количество жёстких ссылок** (hard links).  

> 🔹 **Важно:** Имя файла **не хранится** в inode! Оно лежит в директории, которая связывает имя с inode.  

---

## **2. Как посмотреть inode файла?**  
Команда `ls -i` или `stat`:  
```bash
ls -i file.txt  # Выведет номер inode и имя файла
stat file.txt   # Подробная информация (включая inode)
```
**Пример вывода `stat`:**  
```
  File: file.txt
  Size: 1024       Blocks: 8          IO Block: 4096   regular file
Device: 802h/2050d  Inode: 1234567    Links: 1
Access: 2024-05-10 15:00:00.000000000 +0300
Modify: 2024-05-10 14:30:00.000000000 +0300
Change: 2024-05-10 14:35:00.000000000 +0300
 Birth: -
```
Здесь `Inode: 1234567` — уникальный номер inode.  

---

## **3. Зачем нужны inode?**  
### **1. Жёсткие ссылки (Hard Links)**  
- Жёсткая ссылка — это дополнительное имя файла, ссылающееся на тот же inode.  
- Файл удаляется только когда количество ссылок (`Links` в `stat`) становится `0`.  

**Создание жёсткой ссылки:**  
```bash
ln file.txt hardlink.txt  # Теперь file.txt и hardlink.txt — один и тот же inode
```

### **2. Отслеживание файлов**  
- Inode не меняются при **переименовании** или **перемещении** файла в той же файловой системе.  
- Программы (например, `tail -f`) используют inode для слежения за файлами, даже если их имена изменились.  

### **3. Восстановление данных**  
Утилиты типа `debugfs` могут искать файлы по inode, если повреждена структура директорий.  

---

## **4. Inode и файловые системы**  
- **Ext4, XFS, Btrfs** — все используют inode.  
- **Максимальное количество inode** задаётся при создании ФС (например, `mkfs.ext4 -N 1000000`).  
  - Проверить: `df -i` (столбец `Inodes`).  
- **Закончились inode?** Даже при свободном месте нельзя создать файлы!  

**Пример проверки inode в системе:**  
```bash
df -i  # Показать использование inode
```
Вывод:  
```
Filesystem     Inodes  IUsed  IFree IUse% Mounted on
/dev/sda1     1.2M    500K   700K   42%  /
```

---

## **5. Особенности**  
- **Inode уникальны только в пределах одной ФС.**  
  - При копировании между разными ФС создаётся новый inode.  
- **Символические ссылки (symlinks) имеют свои inode.**  
  ```bash
  ln -s file.txt symlink.txt  # symlink.txt — новый inode, указывающий на file.txt
  ```
- **Удаление файла = освобождение inode.**  

---

## **6. Проблемы с inode**  
### **1. Закончились inode**  
**Симптомы:**  
```bash
touch newfile.txt  # Ошибка: No space left on device (хотя место есть)
```
**Решение:**  
- Удалить ненужные мелкие файлы.  
- Пересоздать ФС с бóльшим числом inode.  

### **2. Потерянные inode (orphaned inodes)**  
Если файл удалён, но процесс держит его открытым (например, лог-файл сервиса), inode остаётся занятым до завершения процесса.  

**Как найти такие файлы?**  
```bash
lsof +aL1 /mount/point  # Показать файлы с удалёнными именами (но открытые процессами)
```

---

## **Вывод**  
- **Inode — это «паспорт» файла** в Unix/Linux.  
- Они хранят метаданные, но не имена.  
- Критичны для работы жёстких ссылок и файловых операций.  
- Если `df -i` показывает 100% — пора чистить систему!
