В Linux файловая система использует **ссылки** для связи файлов с их данными на диске. Существует два типа ссылок: **жёсткие (hard links)** и **символические (мягкие) ссылки (soft/symbolic links)**.  
---
## 🔗 **Жёсткие ссылки (Hard Links)**
- **Определение**: Это прямая ссылка на **inode** (информационную структуру файла) на диске.  
- **Особенности**:
  - Создаётся командой `ln исходный_файл жёсткая_ссылка`.
  - Все жёсткие ссылки равноправны — нет "оригинала", все они указывают на одни и те же данные.
  - Если удалить одну из жёстких ссылок, данные останутся доступны через другие ссылки.
  - Работает **только в пределах одной файловой системы** (нельзя ссылаться на файлы на другом разделе или диске).
  - Нельзя создать жёсткую ссылку на директорию (только на файлы).
- **Пример**:
  ```bash
  touch file.txt
  ln file.txt hardlink.txt  # создаём жёсткую ссылку
  ```
  Теперь `file.txt` и `hardlink.txt` указывают на один и тот же inode.

## 🔄 **Символические (мягкие) ссылки (Soft/Symbolic Links)**
- **Определение**: Это отдельный файл, который содержит **путь к другому файлу** (аналог "ярлыка" в Windows).  
- **Особенности**:
  - Создаётся командой `ln -s исходный_файл мягкая_ссылка`.
  - Если удалить исходный файл, символическая ссылка станет **"битой"** (dangling link).
  - Может ссылаться на файлы **в других файловых системах** и даже на директории.
  - Права доступа у символической ссылки не имеют значения — важны права исходного файла.
- **Пример**:
  ```bash
  touch original.txt
  ln -s original.txt symlink.txt  # создаём мягкую ссылку
  ```
  Если удалить `original.txt`, `symlink.txt` будет вести в никуда.

## 🔍 **Различия между жёсткими и мягкими ссылками**
| Характеристика          | Жёсткая ссылка (Hard Link) | Мягкая ссылка (Symbolic Link) |
|-------------------------|---------------------------|------------------------------|
| **Связь с файлом**      | Прямая ссылка на inode    | Ссылка по имени файла        |
| **Удаление оригинала**  | Данные остаются           | Ссылка становится битой      |
| **Файловая система**    | Только та же ФС           | Можно ссылаться между ФС     |
| **Ссылки на директории**| ❌ Нет                    | ✅ Да                        |
| **Команда создания**    | `ln`                     | `ln -s`                      |

## 🛠 **Полезные команды**
- Проверить, куда ведёт символическая ссылка:
  ```bash
  ls -l symlink.txt
  ```
- Узнать inode файла (для жёстких ссылок):
  ```bash
  ls -i file.txt
  ```
- Найти все жёсткие ссылки на файл:
  ```bash
  find / -samefile file.txt 2>/dev/null
  ```

**inode у файла и его символической (мягкой) ссылки — разные**.  

### 🔍 **Как это работает?**
1. **Исходный файл** имеет свой собственный **inode**, который хранит метаданные (права, владельца, размер и т. д.) и указатели на данные на диске.  
   ```bash
   touch file.txt
   ls -i file.txt  # выведет inode файла, например, 12345
   ```

2. **Символическая ссылка** — это **отдельный файл** со своим **inode**, который содержит только **путь к исходному файлу**.  
   ```bash
   ln -s file.txt symlink.txt
   ls -i symlink.txt  # выведет другой inode, например, 67890
   ```

### 📌 **Проверим на практике**
```bash
$ touch file.txt          # создаём файл
$ ln -s file.txt symlink  # создаём мягкую ссылку
$ ls -li
```
Вывод может выглядеть так:
```
12345 -rw-r--r-- 1 user user 0 May  7 12:00 file.txt
67890 lrwxrwxrwx 1 user user 8 May  7 12:00 symlink -> file.txt
```
- `12345` — inode исходного файла.  
- `67890` — inode символической ссылки.  

### 🔄 **Что происходит при удалении исходного файла?**
- Если удалить `file.txt`, то `symlink` станет **"битой ссылкой"** (dangling symlink), потому что она указывает на несуществующий путь.  
- Проверить можно так:
  ```bash
  rm file.txt
  ls -l symlink  # покажет красный (битый) линк
  ```

### 🔗 **А что с жёсткими ссылками?**
(Для сравнения)  
- Жёсткие ссылки **делят один и тот же inode** с исходным файлом.  
- Пример:
  ```bash
  ln file.txt hardlink
  ls -li
  ```
  Вывод:
  ```
  12345 -rw-r--r-- 2 user user 0 May  7 12:00 file.txt
  12345 -rw-r--r-- 2 user user 0 May  7 12:00 hardlink
  ```
  Оба файла имеют **один и тот же inode (12345)**.

### 🎯 **Вывод**
| Тип ссылки       | Inode такой же, как у оригинала? | Хранит данные? | Зависит от пути? |
|------------------|----------------------------------|----------------|------------------|
| **Жёсткая**      | ✅ Да                            | ✅ Да          | ❌ Нет           |
| **Символическая**| ❌ Нет (свой inode)              | ❌ Нет (только путь) | ✅ Да          |

**Символическая ссылка — это отдельный файл-указатель, а жёсткая — альтернативное имя для тех же данных.**  

Если открыть **мягкую (символическую) ссылку** в Linux, система автоматически перенаправит вас к **исходному файлу**, на который она указывает.  

### 🔍 **Что происходит при открытии?**
1. **Чтение/запись**:  
   - Когда программа (например, `cat`, `vim`, `nano`) пытается открыть символическую ссылку, ядро Linux **следует по пути**, указанному в ссылке, и работает с **оригинальным файлом**.  
   - Пример:  
     ```bash
     echo "Hello" > original.txt
     ln -s original.txt symlink.txt
     cat symlink.txt  # Выведет "Hello" (читает original.txt)
     ```
     Здесь `cat symlink.txt` фактически открывает `original.txt`.

2. **Редактирование**:  
   - Если изменить файл через символическую ссылку, изменения затронут **оригинал**:  
     ```bash
     echo "New line" >> symlink.txt
     cat original.txt  # Будет "Hello\nNew line"
     ```

3. **Удаление**:  
   - Если удалить символическую ссылку (`rm symlink.txt`), оригинальный файл **не пострадает**.  
   - Но если удалить **оригинал** (`rm original.txt`), то попытка открыть `symlink.txt` приведёт к ошибке (битая ссылка):  
     ```bash
     cat symlink.txt  # Ошибка: No such file or directory
     ```

### ⚠️ **Важные нюансы**
- **Права доступа**:  
  Символическая ссылка всегда имеет права `lrwxrwxrwx` (777), но реальные права определяются **оригинальным файлом**.  
  Например, если `original.txt` доступен только для чтения (`-r--r--r--`), то через `symlink.txt` тоже нельзя будет записать данные.

- **Рекурсивные ссылки**:  
  Если символическая ссылка указывает сама на себя (или образует цикл), команды типа `cat` или `ls` выдадут ошибку:  
  ```bash
  ln -s loop.txt loop.txt  # Создаём ссылку на саму себя
  cat loop.txt  # Ошибка: Too many levels of symbolic links
  ```

- **Открытие в программах**:  
  Некоторые программы (например, архиваторы или `cp`) могут работать **либо с самой ссылкой**, либо с файлом, на который она указывает:  
  - `cp symlink.txt backup/` — по умолчанию копирует **оригинал**.  
  - `cp -P symlink.txt backup/` — копирует **саму ссылку**.

### 🛠 **Как проверить, куда ведёт ссылка?**
1. Команда `readlink`:  
   ```bash
   readlink symlink.txt  # Выведет "original.txt"
   ```
2. Подробный вывод `ls -l`:  
   ```bash
   ls -l symlink.txt
   ```
   Пример вывода:  
   ```
   lrwxrwxrwx 1 user user 11 May  7 12:00 symlink.txt -> original.txt
   ```

### 📌 **Вывод**
- **Открытие мягкой ссылки = работа с оригиналом**.  
- Если оригинал удалён — ссылка становится "битой".  
- Права доступа и содержимое зависят от исходного файла, а не от ссылки.  

Примеры:
```bash
# Создаём файл и ссылку
echo "Test" > file.txt
ln -s file.txt link.txt

# Читаем через ссылку
cat link.txt  # Выведет "Test"

# Удаляем оригинал
rm file.txt
cat link.txt  # Ошибка: No such file or directory
```

Если нужно управлять **самим файлом-ссылкой** (а не тем, куда она ведёт), используйте флаги, как в `cp -P` или `tar -h`.
