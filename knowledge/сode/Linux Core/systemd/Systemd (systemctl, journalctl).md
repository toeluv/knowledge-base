# Systemd: Современная Система Инициализации и Журналирования

Systemd - это система инициализации, которая используется в большинстве современных дистрибутивах Linux. Она заменяет собой устаревший SysVinit и предоставляет более эффективный и гибкий способ управления системными сервисами, процессами и настройками. В этот конспект также включены связанные инструменты `journalctl` для ведения журналов и `systemctl` для управления юнитами.

## Преимущества Systemd:

*   **Параллельная загрузка:** Systemd запускает сервисы параллельно, что значительно ускоряет процесс загрузки системы.
*   **Управление зависимостями:** Systemd автоматически определяет зависимости между сервисами и запускает их в правильном порядке.
*   **Удобное логирование:** Journald (компонент Systemd) предоставляет централизованное логирование с мощными возможностями фильтрации и поиска.
*   **Гибкость и расширяемость:** Systemd предлагает широкий спектр настроек и возможностей для управления различными аспектами системы.
*   **Современный API:** Удобный интерфейс командной строки `systemctl` упрощает управление сервисами.

## Основные компоненты Systemd:

1.  **Systemd (the system daemon):** Основной процесс, который отвечает за инициализацию системы, запуск сервисов, обработку событий и управление конфигурацией.
2.  **Units:**  Базовые строительные блоки Systemd.  Они представляют собой различные ресурсы, такие как сервисы, сокеты, точки монтирования, таймеры и т.д. Каждый unit имеет файл конфигурации, определяющий его поведение.  Примеры:
    *   `.service`: Описывает системный сервис (демон).
    *   `.socket`: Описывает сокет, который активирует сервис (например, сетевой сокет).
    *   `.target`: Описывает группы unit'ов и используется для организации и управления процессом загрузки.
    *   `.timer`:  Запускает unit по расписанию (альтернатива `cron`).
3.  **Journald:**  Системный демон, который собирает и хранит логи со всей системы. Journald заменяет собой традиционные файлы логов (например, `/var/log/syslog`, `/var/log/kern.log`) и предоставляет более эффективный и удобный способ управления логами.
4.  **systemctl:**  Утилита командной строки для управления Systemd.  Она используется для запуска, остановки, перезапуска, включения и отключения сервисов, а также для просмотра их статуса и журналов.

## Управление системой с помощью systemctl:

`systemctl` - основная утилита для управления сервисами и другими unit'ами Systemd.

**Основные команды:**

*   **`systemctl start <unit>`**: Запускает указанный unit.
*   **`systemctl stop <unit>`**: Останавливает указанный unit.
*   **`systemctl restart <unit>`**: Перезапускает указанный unit (останавливает и затем запускает).
*   **`systemctl reload <unit>`**:  Перезагружает конфигурацию unit (если unit поддерживает).  Некоторые сервисы могут перезагружать конфигурацию без перезапуска самого сервиса.
*   **`systemctl status <unit>`**: Отображает статус указанного unit (запущен/остановлен, логи, ошибки).
*   **`systemctl enable <unit>`**:  Включает unit для автоматического запуска при загрузке системы (создает симлинк).
*   **`systemctl disable <unit>`**: Отключает unit от автоматического запуска (удаляет симлинк).
*   **`systemctl is-enabled <unit>`**: Проверяет, включен ли unit для автоматического запуска.  Возвращает `enabled`, `disabled`, `static` или `masked`.
*   **`systemctl is-active <unit>`**:  Проверяет, запущен ли unit в данный момент. Возвращает `active`, `inactive` или `failed`.
*   **`systemctl mask <unit>`**:  Маскирует unit, делая невозможным его запуск (ни вручную, ни через зависимости).
*   **`systemctl unmask <unit>`**:  Убирает маску, разрешая запуск.
*   **`systemctl list-units`**:  Список всех unit'ов.
    *   `-t <type>`: Фильтрует по типу unit'а (service, socket, target, etc.).
    *   `-a`: Показывает все unit'ы, включая неактивные.
*   **`systemctl list-dependencies <unit>`**: Показывает зависимости указанного unit.
*   **`systemctl daemon-reload`**:  Перезагружает конфигурацию Systemd после изменения файлов unit'ов в `/etc/systemd/system/`.
*   **`systemctl poweroff`**: Выключает систему.
*   **`systemctl reboot`**: Перезагружает систему.
*   **`systemctl default`**: Загружает default target (обычно `graphical.target` или `multi-user.target`).

**Типы Unit'ов (units):**

*   `service`: Сервисы, демоны (sshd.service, nginx.service)
*   `socket`: Сокеты для активации сервисов (ssh.socket)
*   `target`:  Группы unit'ов (multi-user.target, graphical.target)
*   `timer`: Запуск по расписанию
*   `mount`: Точки монтирования
*   `swap`: Разделы подкачки

**Местоположение файлов Unit'ов:**

*   `/etc/systemd/system/`:  Файлы unit'ов, созданные администратором (имеют приоритет).
*   `/usr/lib/systemd/system/`: Файлы unit'ов, поставляемые пакетами.
*   `/run/systemd/system/`:  Временные файлы unit'ов.

## Примеры:

*   **Запустить сервис Apache:**  `systemctl start apache2.service`
*   **Просмотреть статус сервиса SSH:** `systemctl status sshd.service`
*   **Включить автоматический запуск сервиса Nginx при загрузке:** `systemctl enable nginx.service`
*   **Отключить автоматический запуск сервиса Apache:** `systemctl disable apache2.service`
*   **Перезагрузить конфигурацию Systemd:** `systemctl daemon-reload` (после изменения файлов unit)
*   **Посмотреть все запущенные сервисы:** `systemctl list-units --type=service --state=active`

## Журналирование с помощью journalctl:

`journalctl` - утилита командной строки для просмотра и управления журналами, собранными Journald.

**Основные команды:**

*   **`journalctl`**:  Выводит все логи.
*   **`journalctl -u <unit>`**:  Выводит логи для указанного unit'а (например, `journalctl -u sshd.service`).
*   **`journalctl -f`**:  Выводит логи в реальном времени (аналог `tail -f`).
*   **`journalctl -n <number>`**:  Выводит последние `<number>` строк логов.
*   **`journalctl -r`**:  Выводит логи в обратном порядке (сначала последние).
*   **`journalctl --since "<date>" --until "<date>"`**: Выводит логи в заданном временном диапазоне.  Можно использовать разные форматы дат и времени.
*   **`journalctl -p <priority>`**: Фильтрует логи по уровню приоритета (error, warning, info, debug, etc.).
*   **`journalctl <options> | less`**: Вывод логов в постраничном режиме (для удобного просмотра).
*   **`journalctl _PID=<pid>`**: Выводит логи для указанного PID процесса.
*   **`journalctl _COMM=<name>`**:  Фильтрует логи по имени процесса (например, `_COMM=sshd`).
*   **`journalctl -g "<keyword>"`**:  Поиск по ключевому слову в логах.
*   **`journalctl --vacuum-size=<size>`**: Удаляет старые логи для освобождения места на диске.  `<size>` указывается в байтах (например, `100M`).
*   **`journalctl --vacuum-time=<time>`**: Удаляет логи старше указанного периода времени.

**Примеры:**

*   **Показать логи сервиса SSH:** `journalctl -u sshd.service`
*   **Просмотреть логи с уровнем ошибки и выше:** `journalctl -p err`
*   **Вывести логи последних 10 минут:** `journalctl --since "10 minutes ago"`
*   **Поиск по слову "error" в логах:** `journalctl -g "error"`

## Заключение:

Systemd, systemctl и journalctl - мощный инструментарий для управления современными Linux-системами.  Освоение этих инструментов необходимо для эффективного администрирования и отладки систем.  Практикуйтесь, изучайте файлы unit'ов, и вы сможете максимально эффективно использовать Systemd.
