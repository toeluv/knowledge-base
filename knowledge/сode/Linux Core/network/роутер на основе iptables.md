### **Конспект: Настройка роутера на Linux с помощью `iptables`**  
*(Debian/Ubuntu/CentOS)*  

---

## **🔹 1. Подготовка сервера**
### **Включение форвардинга (проброс пакетов между интерфейсами)**
```bash
# Включить временно
echo 1 > /proc/sys/net/ipv4/ip_forward

# Для сохранения после перезагрузки (добавить в /etc/sysctl.conf)
echo "net.ipv4.ip_forward = 1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p  # Применить изменения
```

---

## **🔹 2. Настройка интерфейсов**
### **Определение интерфейсов**
```bash
ip a
```
Пример:
- **WAN (внешняя сеть):** `eth0` (подключен к интернету)  
- **LAN (локальная сеть):** `eth1` (подключен к локальным устройствам)  

### **Назначение IP для LAN (если нет DHCP)**
```bash
sudo ip addr add 192.168.1.1/24 dev eth1
sudo ip link set eth1 up
```

---

## **🔹 3. Настройка NAT (раздача интернета)**
### **Маскарадинг (подмена исходящего IP на WAN-адрес)**
```bash
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```
- `-t nat` — таблица NAT.  
- `-o eth0` — исходящий интерфейс (WAN).  

### **Разрешение форвардинга между интерфейсами**
```bash
sudo iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT  # LAN -> WAN
sudo iptables -A FORWARD -i eth0 -o eth1 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT  # Ответы из интернета
```

Эти три команды `iptables` настраивают сетевую трансляцию адресов (NAT) для вашей системы, чтобы обеспечить доступ в интернет для устройств во внутренней сети.  Вот подробное объяснение каждой команды:

**1. `sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE`**

*   **`sudo iptables`**: Вызывает утилиту `iptables` с правами суперпользователя.
*   **`-t nat`**: Указывает, что команда будет работать с таблицей `nat`.  Таблица `nat` используется для преобразования сетевых адресов (NAT).
*   **`-A POSTROUTING`**:  Добавляет правило (`-A`) в цепочку `POSTROUTING`. Цепочка `POSTROUTING` обрабатывает пакеты непосредственно перед их отправкой в сеть.
*   **`-o eth0`**:  Указывает, что правило применяется к трафику, который выходит (`-o` - output) через сетевой интерфейс `eth0`.  `eth0` обычно является интерфейсом, который подключен к внешней сети (например, к интернету).
*   **`-j MASQUERADE`**:  Указывает действие (`-j` - jump) для пакетов, соответствующих правилу.  `MASQUERADE` - это тип NAT, который динамически изменяет исходный IP-адрес пакета на IP-адрес интерфейса, через который пакет выходит в интернет.  `MASQUERADE` удобен, когда IP-адрес внешнего интерфейса (eth0) меняется динамически (например, при использовании DHCP).

    **В итоге:** Эта команда настраивает NAT для всех пакетов, которые выходят через `eth0`.  Она заменяет исходный IP-адрес пакетов (IP-адрес клиента из внутренней сети) на IP-адрес интерфейса `eth0`, позволяя устройствам внутренней сети получать доступ в интернет.

**2. `sudo iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT`**

*   **`sudo iptables`**:  Вызывает утилиту `iptables` с правами суперпользователя.
*   **`-A FORWARD`**:  Добавляет правило (`-A`) в цепочку `FORWARD`. Цепочка `FORWARD` обрабатывает пакеты, которые должны быть перенаправлены (пересланы) между интерфейсами.
*   **`-i eth1`**:  Указывает, что правило применяется к трафику, который входит (`-i` - input) через сетевой интерфейс `eth1`. `eth1` обычно является интерфейсом, подключенным к вашей внутренней сети.
*   **`-o eth0`**:  Указывает, что трафик пересылается на интерфейс `eth0` (подключен к внешней сети).
*   **`-j ACCEPT`**:  Указывает действие (`-j`) для пакетов, соответствующих правилу.  `ACCEPT` означает, что пакеты должны быть приняты (разрешены).

    **В итоге:**  Эта команда разрешает пересылку трафика из внутренней сети (`eth1`) в интернет (`eth0`).  Она позволяет пакетам от устройств во внутренней сети достигать интерфейса `eth0` и затем быть отправленными в интернет.

**3. `sudo iptables -A FORWARD -i eth0 -o eth1 -m state --state RELATED,ESTABLISHED -j ACCEPT`**

*   **`sudo iptables`**:  Вызывает утилиту `iptables` с правами суперпользователя.
*   **`-A FORWARD`**:  Добавляет правило (`-A`) в цепочку `FORWARD` (как и предыдущее правило).
*   **`-i eth0`**:  Указывает, что трафик входит через `eth0` (внешний интерфейс).
*   **`-o eth1`**:  Указывает, что трафик выходит через `eth1` (внутренний интерфейс).
*   **`-m state --state RELATED,ESTABLISHED`**:  Использует модуль `state` для проверки состояния пакета.
    *   `--state RELATED`:  Разрешает трафик, который связан с существующими соединениями (например, ответы на запросы, отправленные с клиентских устройств во внутренней сети).
    *   `--state ESTABLISHED`: Разрешает трафик, который является частью уже установленных соединений.
*   **`-j ACCEPT`**:  Указывает действие (`-j`) для пакетов, соответствующих правилу: принять (разрешить).

    **В итоге:**  Эта команда разрешает ответный трафик, связанный с установленными соединениями, который поступает из интернета (`eth0`) на устройства во внутренней сети (`eth1`).  Это необходимо для того, чтобы устройства во внутренней сети могли получать ответы на свои запросы из интернета.

**В целом:**

Эти три команды вместе реализуют базовую функциональность NAT-маршрутизатора:

1.  **`MASQUERADE`**:  Преобразует исходный IP-адрес пакетов, исходящих из внутренней сети, на IP-адрес внешнего интерфейса (`eth0`), позволяя устройствам внутренней сети отправлять трафик в интернет.
2.  **`FORWARD (eth1 -> eth0)`**: Разрешает пересылку трафика из внутренней сети во внешнюю сеть (в интернет).
3.  **`FORWARD (eth0 -> eth1) RELATED,ESTABLISHED`**: Разрешает ответный трафик (ответы на запросы, отправленные из внутренней сети) из внешней сети во внутреннюю сеть, поддерживая существующие соединения.

Эти правила необходимы для того, чтобы ваша система могла функционировать как маршрутизатор, обеспечивая доступ в интернет для устройств, подключенных к внутренней сети.  Убедитесь, что вы заменили `eth0` и `eth1` на правильные имена ваших сетевых интерфейсов.

## **🔹 4. Базовый фаервол**
### **Разрешить локальный трафик**
```bash
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A OUTPUT -o lo -j ACCEPT
```

### **Разрешить SSH (если управление через WAN)**
```bash
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

### **Блокировать всё остальное**
```bash
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
```

---

## **🔹 5. Проброс портов (опционально)**
### **Пример: проброс порта 8080 на внутренний сервер 192.168.1.2:80**
```bash
sudo iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.2:80
sudo iptables -A FORWARD -p tcp -d 192.168.1.2 --dport 80 -j ACCEPT
```

---

## **🔹 6. Сохранение правил**
### **Debian/Ubuntu**
```bash
sudo apt install iptables-persistent
sudo netfilter-persistent save
```
Или вручную:
```bash
sudo iptables-save > /etc/iptables/rules.v4
```

### **CentOS/RHEL**
```bash
sudo service iptables save
```

## **🔹 7. Настройка клиентов**
На локальных устройствах (LAN) укажите:  
- **Шлюз:** `192.168.1.1` (IP роутера в LAN)  
- **DNS:** `8.8.8.8` или ваш провайдерский DNS.  

---

## **🔹 Итоговая схема работы**
1. ПК в LAN (`192.168.1.2`) отправляет запрос в интернет.  
2. Роутер подменяет его IP на свой WAN-адрес (`MASQUERADE`).  
3. Ответ из интернета возвращается на роутер, который перенаправляет его обратно в LAN.  

---

## **❗ Важно**
- Не блокируйте SSH, если подключены удалённо!  
- Для IPv6 используйте `ip6tables`.  
- Проверяйте связь:  
  ```bash
  ping 8.8.8.8  # С роутера
  ping 192.168.1.1  # С клиента
  ```

Теперь ваш Linux-сервер работает как роутер! 🚀
