**1.  Использование NetworkManager (Рекомендуется):**

   Если вы используете NetworkManager,  который является стандартным для многих современных дистрибутивов Linux, вам нужно создать или изменить соединение, чтобы указать статический IP-адрес.  Это самый простой и рекомендуемый способ.

   *   **Проверьте наличие соединения:** Убедитесь, что NetworkManager управляет интерфейсом `eth1`.  Если это так, команда `nmcli connection show` должна показать соединение, связанное с `eth1`.  Если соединения нет, следуйте инструкциям раздела "Создание нового соединения (Static IP-адрес)" ниже.
   *   **Измените существующее соединение (если оно есть):**
       *   **Найти имя соединения:** Найдите имя существующего соединения для `eth1` с помощью `nmcli connection show`. Запишите имя (например, "eth1-connection").
       *   **Измените настройки IPv4:**
           ```bash
           sudo nmcli connection modify "<имя_соединения>" ipv4.address 192.168.1.1/24
           sudo nmcli connection modify "<имя_соединения>" ipv4.gateway 192.168.1.254  # Замените на свой шлюз
           sudo nmcli connection modify "<имя_соединения>" ipv4.method manual  # Укажите метод "ручной" (статический)
           sudo nmcli connection modify "<имя_соединения>" ipv4.dns 8.8.8.8  # Укажите DNS сервер
           ```
           Замените `<имя_соединения>` на имя вашего соединения и `192.168.1.254`, `8.8.8.8` на соответствующие значения вашей сети.
       *   **Перезагрузите соединение:**
           ```bash
           sudo nmcli connection down "<имя_соединения>" && sudo nmcli connection up "<имя_соединения>"
           ```
       *   **Проверьте конфигурацию:**  Убедитесь, что настройки применены:
           ```bash
           nmcli connection show "<имя_соединения>"
           ```
           Проверьте, что указаны правильный IP-адрес, маска подсети, шлюз и DNS.
           ```bash
           ip addr show eth1
           ```
   *   **Создание нового соединения (Static IP-адрес):**  Если у вас нет соединения для `eth1`, создайте его:
       ```bash
       sudo nmcli connection add type ethernet con-name "Static eth1" ifname eth1 ip4 192.168.1.1/24 gw4 192.168.1.254 ipv4.method manual
       ```
       *   `type ethernet`:  Тип соединения (Ethernet).
       *   `con-name "Static eth1"`:  Имя соединения.
       *   `ifname eth1`:  Имя интерфейса.
       *   `ip4 192.168.1.1/24`:  IP-адрес и маска подсети.
       *   `gw4 192.168.1.254`:  Шлюз по умолчанию.  Замените на свой шлюз.
       *   `ipv4.method manual`: Указывает, что необходимо использовать статический ip.
       *   `ipv4.dns 8.8.8.8`: Укажите DNS сервер
       После выполнения этой команды, перезагрузите соединение:
           ```bash
           sudo nmcli connection down "Static eth1" && sudo nmcli connection up "Static eth1"
           ```
   *   **Включение автоматического подключения (необязательно):** Если вы хотите, чтобы соединение подключалось автоматически при загрузке, выполните:
       ```bash
       sudo nmcli connection modify "Static eth1" connection.autoconnect yes
       ```
       Замените "Static eth1" на имя вашего соединения.

**2. Использование /etc/network/interfaces (Если NetworkManager не используется или отключен):**

   Этот метод менее предпочтителен, так как он может конфликтировать с NetworkManager, но он необходим, если NetworkManager не используется.

   *   **Отредактируйте файл `/etc/network/interfaces`:** Откройте файл `/etc/network/interfaces` с помощью текстового редактора с правами администратора (например, `sudo nano /etc/network/interfaces`).
   *   **Добавьте или измените записи для `eth1`:** Добавьте следующие строки в файл, заменив IP-адрес, маску подсети и шлюз на ваши значения:

       ```
       auto eth1
       iface eth1 inet static
           address 192.168.1.1
           netmask 255.255.255.0
           gateway 192.168.1.254  # Замените на свой шлюз (если нужен)
           dns-nameservers 8.8.8.8  # Укажите DNS-сервер (если нужен)
       ```
       *   `auto eth1`:  Интерфейс `eth1` будет автоматически активироваться при загрузке.
       *   `iface eth1 inet static`:  Указывает, что `eth1` будет использовать статический IP-адрес.
       *   `address`: IP-адрес.
       *   `netmask`: Маска подсети.
       *   `gateway`: Шлюз по умолчанию (если нужен).
       *   `dns-nameservers`: DNS-сервер (если нужен).

   *   **Сохраните изменения:** Сохраните файл `/etc/network/interfaces`.
   *   **Перезапустите сетевую службу:** Перезапустите сетевую службу, чтобы применить изменения.  Для этого можно использовать одну из следующих команд (выберите ту, которая работает в вашей системе):

       ```bash
       sudo systemctl restart networking  # Ubuntu/Debian/systemd
       sudo service networking restart   # Debian/Ubuntu (старые версии)
       sudo /etc/init.d/networking restart # Debian/Ubuntu (совсем старые версии)
       ```
       или
       ```bash
       sudo systemctl restart network # Fedora/CentOS/RHEL
       ```
   *   **Проверьте IP-адрес:**  Убедитесь, что IP-адрес назначен интерфейсу `eth1`, используя команду `ip addr show eth1`.

**Важные замечания:**

*   **Шлюз по умолчанию:**  Укажите правильный шлюз по умолчанию (gateway) для вашего интерфейса, если вам нужен доступ к другим сетям или к интернету.
*   **DNS-серверы:**  Укажите DNS-серверы, чтобы ваша система могла разрешать доменные имена в IP-адреса.
*   **Конфликты:** Убедитесь, что вы назначаете *уникальный* IP-адрес интерфейсу `eth1`.  Избегайте конфликтов с другими устройствами в вашей сети.
*   **`sudo`:**  Для выполнения этих команд требуются права администратора (использование `sudo`).
*   **Выбор метода:** Отдавайте предпочтение NetworkManager, если это возможно. Он обычно более прост в использовании и более гибкий.
*   **Резервное копирование:**  Перед внесением изменений в файлы конфигурации рекомендуется создать их резервные копии.  Например: `sudo cp /etc/network/interfaces /etc/network/interfaces.bak`.

Если вы хотите, чтобы ваша виртуальная машина с настроенным `eth1` действовала как маршрутизатор для внутренней сети, нужно выполнить несколько дополнительных шагов после назначения статического IP-адреса, чтобы включить пересылку IP-пакетов (IP forwarding) и настроить NAT (Network Address Translation), если требуется доступ в интернет для устройств во внутренней сети.

**1. Включите IP Forwarding:**

IP Forwarding позволяет вашей системе пересылать IP-пакеты между разными сетевыми интерфейсами.

*   **Включите IP Forwarding временно (до перезагрузки):**

    ```bash
    sudo sysctl -w net.ipv4.ip_forward=1
    ```

*   **Включите IP Forwarding постоянно (после перезагрузки):**

    *   Отредактируйте файл `/etc/sysctl.conf` (или `/etc/sysctl.d/99-sysctl.conf` в некоторых системах):

        ```bash
        sudo nano /etc/sysctl.conf
        ```

    *   Раскомментируйте или добавьте строку:

        ```
        net.ipv4.ip_forward=1
        ```

    *   Сохраните файл и примените изменения:

        ```bash
        sudo sysctl -p
        ```

**2. Настройте NAT (если нужен доступ в интернет для внутренней сети):**

Если вы хотите, чтобы устройства во внутренней сети (подключенные к `eth1`) имели доступ в интернет через вашу виртуальную машину, вам нужно настроить NAT (Network Address Translation).  Предполагается, что у вас есть другой интерфейс (например, `eth0`), подключенный к внешней сети (например, через NAT в VirtualBox).

*   **Определите интерфейс, подключенный к внешней сети:**  Узнайте имя интерфейса, который имеет доступ в интернет (например, `eth0`).

*   **Настройте NAT с помощью `iptables`:**

    *   **Включите NAT временно (до перезагрузки):**

        ```bash
        sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
        sudo iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT
        sudo iptables -A FORWARD -i eth0 -o eth1 -m state --state RELATED,ESTABLISHED -j ACCEPT
        ```

        *   `iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE`:  Включает NAT для трафика, выходящего через интерфейс `eth0` (интерфейс, подключенный к интернету).  MASQUERADE - это тип NAT, который динамически использует IP-адрес внешнего интерфейса.
        *   `iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT`:  Разрешает пересылку трафика с интерфейса `eth1` (внутренняя сеть) на интерфейс `eth0` (интернет).
        *   `iptables -A FORWARD -i eth0 -o eth1 -m state --state RELATED,ESTABLISHED -j ACCEPT`: Разрешает ответный трафик с интерфейса `eth0` на интерфейс `eth1` для установленных соединений.

    *   **Настройте NAT постоянно (после перезагрузки):**  `iptables` правила не сохраняются после перезагрузки.  Чтобы сохранить правила, необходимо использовать `iptables-persistent` (в Debian/Ubuntu) или аналогичный инструмент.

        *   **Установите `iptables-persistent`:**

            ```bash
            sudo apt update
            sudo apt install iptables-persistent
            ```

        *   Во время установки `iptables-persistent` вам будет предложено сохранить текущие правила IPv4 и IPv6.  Выберите `Yes`.

        *   **Альтернативный способ (если `iptables-persistent` не доступен):** Создайте скрипт, который будет выполнять команды `iptables` при загрузке системы.

            *   Создайте скрипт (например, `/etc/network/if-up.d/iptables-nat`):

                ```bash
                sudo nano /etc/network/if-up.d/iptables-nat
                ```

                Со следующим содержимым:

                ```bash
                #!/bin/sh
                iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
                iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT
                iptables -A FORWARD -i eth0 -o eth1 -m state --state RELATED,ESTABLISHED -j ACCEPT
                exit 0
                ```

            *   Сделайте скрипт исполняемым:

                ```bash
                sudo chmod +x /etc/network/if-up.d/iptables-nat
                ```

            *   Этот скрипт будет выполняться каждый раз, когда поднимается сетевой интерфейс.

**3. Настройка маршрутизации на клиентских машинах (во внутренней сети):**

На каждой клиентской машине, подключенной к внутренней сети (к `eth1` вашей виртуальной машины), необходимо настроить маршрут по умолчанию (default gateway), указывающий на IP-адрес интерфейса `eth1` вашей виртуальной машины ( `192.168.1.1` в нашем примере).

*   Например, если у вас другая Linux-машина во внутренней сети, вы можете настроить маршрут по умолчанию с помощью команды:

    ```bash
    sudo ip route add default via 192.168.1.1
    ```

    Для сохранения этой настройки после перезагрузки, вам нужно добавить ее в конфигурацию сети этой клиентской машины (например, в файл `/etc/network/interfaces` или через NetworkManager).

*   Для Windows, вы можете настроить шлюз по умолчанию в настройках сетевого адаптера.

**Пример конфигурации (сводка):**

*   **Виртуальная машина (маршрутизатор):**
    *   `eth0`: Подключен к внешней сети (например, через NAT в VirtualBox). Получает IP-адрес динамически.
    *   `eth1`: Подключен к внутренней сети. Статический IP-адрес `192.168.1.1/24`.
    *   IP Forwarding: Включен.
    *   NAT: Настроен для трафика, выходящего через `eth0`.

*   **Клиентская машина (во внутренней сети):**
    *   Подключена к внутренней сети.
    *   IP-адрес: Статический IP-адрес в диапазоне `192.168.1.2` - `192.168.1.254` (например, `192.168.1.10`).
    *   Шлюз по умолчанию: `192.168.1.1` (IP-адрес `eth1` на виртуальной машине).
    *   DNS-сервер:  `8.8.8.8` (или другой DNS-сервер).

**Важно:**

*   **Брандмауэр:**  Убедитесь, что брандмауэр на вашей виртуальной машине (маршрутизаторе) не блокирует трафик между интерфейсами `eth0` и `eth1`.
*   **Имена интерфейсов:** Замените `eth0` и `eth1` на фактические имена ваших сетевых интерфейсов.
*   **Диапазоны IP-адресов:**  Используйте диапазоны IP-адресов, которые соответствуют вашей сетевой конфигурации.

В контексте настройки виртуальной машины, выступающей в роли маршрутизатора, параметр `ipv4.gateway` в командах `nmcli` для интерфейса `eth1` (подключенного к внутренней сети) настраивается **не совсем так, как это обычно делается на клиентских машинах**.  Вот как это правильно сделать и почему:

**Понимание роли gateway (шлюза по умолчанию):**

*   **На клиентских машинах:** Шлюз по умолчанию - это IP-адрес устройства (обычно маршрутизатора), через которое клиентская машина отправляет трафик, предназначенный для сетей, отличных от ее собственной.
*   **На маршрутизаторе (ваша виртуальная машина):** Шлюз по умолчанию (gateway) на интерфейсе, подключенном к внутренней сети (`eth1` в вашем случае) должен быть настроен таким образом, чтобы пакеты, предназначенные для других сетей, пересылались на интерфейс, который подключен к внешней сети (например, `eth0`).  Но, в вашем случае, IP-адрес 192.168.1.254 – это **не** IP-адрес самого маршрутизатора.

**Правильная настройка `ipv4.gateway` для внутренней сети (eth1):**

Ваша виртуальная машина будет шлюзом для устройств внутренней сети. Значит, вы должны указать `ipv4.gateway` таким образом, чтобы пакеты, не предназначенные для вашей сети `192.168.1.0/24` (в данном примере), отправлялись на интерфейс, подключенный к внешней сети (например, `eth0`).

1.  **Узнайте IP-адрес eth0 (внешний интерфейс):** Вам нужно выяснить IP-адрес интерфейса `eth0` на вашей виртуальной машине.  Этот IP-адрес будет использоваться в качестве gateway для интерфейса `eth1` (если ваша цель - обеспечить доступ в интернет для клиентов в внутренней сети).  Запустите `ip addr` или `ifconfig` в терминале на вашей виртуальной машине и найдите интерфейс `eth0`. Найдите строчку, в которой указан inet (например, `inet 10.0.2.15/24`).  IP-адрес, указанный после `inet`, это и есть IP-адрес `eth0`.

2.  **Настройка `ipv4.gateway` (если IP-адрес eth0 не динамический):**

    *   Используйте этот IP-адрес (IP-адрес `eth0`) в качестве значения `ipv4.gateway`:
        ```bash
        sudo nmcli connection modify "<имя_соединения>" ipv4.gateway <IP_адрес_eth0>
        ```
        Замените `<имя_соединения>` на имя вашего соединения для `eth1` (подключенного к внутренней сети).  Замените `<IP_адрес_eth0>` на фактический IP-адрес, который вы нашли для `eth0`.

3.  **Настройка шлюза на клиентских машинах внутренней сети (Самое важное):**

    *   На каждой клиентской машине (устройстве) во внутренней сети, вам нужно настроить шлюз по умолчанию (gateway), указывающий на *IP-адрес интерфейса `eth1` вашей виртуальной машины*.  В вашем примере, это будет `192.168.1.1`.

    *   На Linux-системах, это можно сделать с помощью команды:
        ```bash
        sudo ip route add default via 192.168.1.1
        ```
        Эта команда указывает системе, что весь трафик, не предназначенный для локальной сети, следует направлять на IP-адрес 192.168.1.1.
    *   Для постоянной работы необходимо настроить маршрут по умолчанию в конфигурации сети (например, в файле `/etc/network/interfaces` или через NetworkManager).

    ```bash
    sudo nmcli connection modify "Имя_Соединения_Eth1" ipv4.address 192.168.1.1/24 # IP для eth1
    ```

    *   Настройте шлюз по умолчанию (gateway):

**Почему 192.168.1.254 не подходит:**

IP-адрес `192.168.1.254` (как вы указываете) используется в качестве шлюза по умолчанию *на клиентских машинах*.  Но ваша виртуальная машина будет сама по себе выполнять роль шлюза, поэтому вы должны указать в качестве шлюза (gateway) для eth1 именно *IP-адрес интерфейса, который подключен к внешней сети (eth0)*. Если вы укажете 192.168.1.254, то пакеты будут отправлены на несуществующий адрес и не дойдут до интернета.

**Важные моменты:**

*   **Последовательность:** Выполняйте шаги в указанном порядке.
*   **Перепроверка:** После внесения изменений, проверьте, работает ли сеть.  Проверьте подключение с помощью `ping` (с клиентской машины во внутренней сети: ping 8.8.8.8 - чтобы проверить доступ в интернет).  Проверьте маршрутизацию (`ip route` на клиентской машине).
*   **Безопасность:**  Убедитесь, что вы понимаете основы брандмауэра и безопасности сети.
*   **Перезагрузка:** После настройки, перезагрузите вашу виртуальную машину и клиентские машины для проверки.
*   **Сохранение правил `iptables`:** Если вы используете `iptables`, вам нужно настроить сохранение этих правил, чтобы они применялись после перезагрузки.

При правильной конфигурации, устройства во внутренней сети смогут получить доступ в Интернет через вашу виртуальную машину-маршрутизатор.
