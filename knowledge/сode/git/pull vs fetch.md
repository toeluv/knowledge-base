## 🔄 Разница между `git pull` и `git fetch`

Обе команды получают изменения с удалённого репозитория, но делают это **по-разному**.

---

### 🐢 `git fetch`

#### 📌 Что делает:

* Загружает **все изменения** с удалённого репозитория: новые ветки, коммиты, теги.
* **Не трогает** рабочую директорию и текущую ветку.
* Обновляет только ссылки в `.git/refs/remotes/`.

#### 🛠 Примеры:

```bash
git fetch origin      # Получает изменения из origin
git fetch --all       # Получает из всех удалённых
```

#### 🧠 Когда использовать:

* Когда нужно **увидеть изменения**, но не вносить их в локальный код.
* Для **обновления информации** о состоянии удалённых веток.
* Перед созданием новой ветки из актуального удалённого состояния.

#### 🔍 Визуально:

```
До fetch:
  main:         A---B---C
  origin/main:  A---B---C

После fetch:
  main:         A---B---C
  origin/main:  A---B---C---D---E
```

---

### ⚡ `git pull`

#### 📌 Что делает:

* Делает `git fetch` ➕ затем `git merge` (или `rebase`).
* Обновляет текущую ветку **и рабочие файлы**.
* Может создать **слияние (merge commit)**.

#### 🛠 Примеры:

```bash
git pull origin main  # Получить и объединить изменения из origin/main
git pull              # Использует по умолчанию настроенную ветку
```

#### 🧠 Когда использовать:

* Когда хочешь **сразу обновить** свою ветку.
* Если не нужно предварительно проверять изменения.
* При работе в одиночку или на доверенном репозитории.

#### 🔃 Визуально:

```
До pull:
  main:         A---B---C
  origin/main:  A---B---C---D---E

После pull:
  main:         A---B---C---M
                             /
                    D---E--- 
(M — merge commit)
```

---

## 📊 Сводная таблица сравнения

| Характеристика               | `git fetch`               | `git pull`                |
| ---------------------------- | ------------------------- | ------------------------- |
| Обновляет рабочую директорию | ❌ Нет                     | ✅ Да                      |
| Выполняет merge/rebase       | ❌ Нет                     | ✅ Да                      |
| Создаёт коммиты              | ❌ Нет                     | ✅ Возможно (merge-коммит) |
| Опасность конфликтов         | 🔐 Безопасно              | ⚠️ Возможны конфликты     |
| Контроль над процессом       | ✅ Полный                  | ❌ Минимальный             |
| Подходит для                 | Анализа и ревью изменений | Быстрой синхронизации     |

---

## ✅ Рекомендации по использованию

### 🧼 Безопасный подход:

```bash
git fetch
git log origin/main..main       # Посмотреть изменения
git merge origin/main           # Слить вручную
```

### 🔄 Современный рабочий процесс:

```bash
git fetch
git rebase origin/main          # "Чистая" история без merge-коммитов
```

### ⚙️ Настройка pull на rebase:

```bash
git config --global pull.rebase true
```
