### **Сортировка выбором (Selection Sort)**  
**Простой, но неэффективный алгоритм сортировки, работающий за O(n²).**  

---

## **📌 Основная идея**  
1. **Разделение массива** на две части:  
   - **Отсортированная** (слева, изначально пустая).  
   - **Неотсортированная** (справа, весь массив).  
2. **На каждом шаге** алгоритм:  
   - Находит **минимальный элемент** в неотсортированной части.  
   - Меняет его местами с **первым элементом неотсортированной части**.  
   - "Расширяет" отсортированную часть на 1 элемент.  

---

## **📝 Алгоритм по шагам**  
1. **Инициализация**:  
   - Всё массив считается **неотсортированным**.  
2. **Проход по массиву**:  
   - Для каждого `i` от `0` до `n-1`:  
     - Найти **индекс минимального элемента** в неотсортированной части (`от i до конца`).  
     - Поменять местами `arr[i]` и `arr[min_index]`.  
3. **Завершение**:  
   - После `n` итераций массив отсортирован.

**Пример:** Сортировка `[29, 10, 14, 37, 13]`  

| Шаг | Состояние массива             | Действие                          |
|-----|-------------------------------|-----------------------------------|
| 1   | [**29**, 10, 14, 37, 13]      | Найден минимум `10` (индекс 1). Меняем с `29`. |
| 2   | [10, **29**, 14, 37, 13]      | Минимум `13` (индекс 4). Меняем с `29`. |
| 3   | [10, 13, **14**, 37, 29]      | Минимум `14` (уже на месте). |
| 4   | [10, 13, 14, **37**, 29]      | Минимум `29`. Меняем с `37`. |
| 5   | [10, 13, 14, 29, **37**]      | Готово! |

---

## **⚡ Сложность**  
- **Время**:  
  - **Худший случай**: O(n²) — даже если массив почти отсортирован.  
  - **Лучший случай**: O(n²) — нет оптимизации для уже упорядоченных данных.  
- **Память**: O(1) — сортировка **на месте** (не требует дополнительной памяти).  

---

## **🔄 Стабильность**  
- **Нет** (меняет порядок одинаковых элементов).  
  Пример: `[5a, 2, 5b, 1]` → `[1, 2, 5b, 5a]` (порядок `5a` и `5b` изменился).  

---

## **✅ Плюсы и минусы**  
| **Преимущества**               | **Недостатки**                  |
|--------------------------------|----------------------------------|
| Простота реализации.           | Медленный для больших массивов. |
| Работает за O(1) по памяти.    | Всегда O(n²), даже в лучшем случае. |
| Удобен для маленьких массивов. | Нестабильный. |

---

## **🚀 Когда использовать?**  
- На маленьких данных (например, `n < 1000`).  
- Когда важна **простота кода**, а не скорость.  
- В учебных целях (базовый алгоритм для понимания сортировок).  

---

## **💡 Аналог из жизни**  
Представьте, что вы раскладываете колоду карт:  
1. Ищете **самую маленькую карту** в колоде.  
2. Кладете ее в начало новой стопки.  
3. Повторяете, пока все карты не закончатся.  

---

## **📌 Итог**  
- **Как работает**: Последовательно выбирает минимумы и ставит их в начало.  
- **Сложность**: O(n²) времени, O(1) памяти.  
- **Применение**: Обучение, маленькие массивы.  

**Финальный пример сортировки:**  
```java
public class SelectionSort {
  public static int[] sort(int[] toSort) {
    for (int i = 0; i < toSort.length - 1; i++) {
      int min = i;
      for (int j = i + 1; j < toSort.length; j++) {
        if (toSort[j] < toSort[min]) {
          min = j;
        }
      }
      swap(toSort, i, min);
    }
    return toSort;
  }

  private static void swap(int[] array, int idxOfFirst, int idxOfSecond) {
    int buffer = array[idxOfFirst];
    array[idxOfFirst] = array[idxOfSecond];
    array[idxOfSecond] = buffer;
  }
}
```
