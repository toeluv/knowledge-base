### **Сложность алгоритмов**  

#### **1. Зачем нужна оценка сложности?**  
Сложность алгоритма помогает понять, как быстро растут затраты времени и памяти при увеличении размера входных данных (`n`).  

**Основные цели:**  
✅ Сравнение алгоритмов  
✅ Прогнозирование производительности  
✅ Оптимизация кода  

---

#### **2. Виды сложности**  

| Тип сложности       | Что оценивает?                     | Пример использования |  
|---------------------|-----------------------------------|----------------------|  
| **Временная**       | Количество операций               | Время сортировки массива |  
| **Пространственная**| Объём используемой памяти         | Память для хранения данных |  
| **Амортизационная** | Средние затраты за несколько операций | Добавление элементов в динамический массив |  

---

#### **3. О-нотация: шкала сложности**  

**Сводная таблица:**  

| Нотация  | Скорость роста | Пример алгоритма               | Когда встречается? |  
|----------|---------------|--------------------------------|--------------------|  
| **O(1)**      | Не зависит от `n` | Доступ к элементу массива      | Идеальный вариант |  
| **O(log n)**  | Очень медленно | Бинарный поиск                 | Алгоритмы с делением пополам |  
| **O(n)**      | Пропорционально `n` | Линейный поиск                 | Перебор элементов |  
| **O(n log n)**| Быстрее, чем квадратичная | Быстрая сортировка (QuickSort) | Эффективные алгоритмы сортировки |  
| **O(n²)**     | Быстро растёт  | Пузырьковая сортировка         | Вложенные циклы |  
| **O(2ⁿ)**     | Очень быстро   | Перебор всех подмножеств       | Полный перебор |  
| **O(n!)**     | Крайне быстро  | Генерация всех перестановок    | Задачи комбинаторики |  

**Как запомнить?**  
📉 Чем "ниже" сложность в таблице — тем лучше!  
🚨 **O(n²), O(2ⁿ), O(n!)** — опасные зоны для больших данных.  

---

#### **4. Как определить сложность?**  

**Простые правила:**  
1. **Один цикл по массиву** → `O(n)`  
   ```python
   for i in range(n):  # O(n)
       print(i)
   ```  
2. **Два вложенных цикла** → `O(n²)`  
   ```python
   for i in range(n):      # O(n)
       for j in range(n):  # O(n) → O(n²)
           print(i, j)
   ```  
3. **Рекурсия с делением** → `O(log n)`  
   ```python
   def binary_search(arr, low, high, target):  # Делим массив пополам
       if high >= low:
           mid = (high + low) // 2
           if arr[mid] == target:
               return mid
           elif arr[mid] > target:
               return binary_search(arr, low, mid - 1, target)
           else:
               return binary_search(arr, mid + 1, high, target)
       else:
           return -1
   ```  

**Упрощение:**  
- Отбрасываем константы: `O(2n + 100)` → `O(n)`  
- Оставляем самый "тяжёлый" член: `O(n² + n log n)` → `O(n²)`

#### **5. Примеры из жизни**  

🔹 **O(1)** — включение света в комнате (не зависит от количества лампочек).  
🔹 **O(n)** — поиск книги в неупорядоченной стопке (проверяем одну за другой).  
🔹 **O(log n)** — поиск слова в словаре (открываем на случайной странице и сужаем диапазон).  
🔹 **O(n²)** — знакомство каждого человека в комнате с каждым (10 человек → 100 рукопожатий).  

---

#### **6. Что делать с этой информацией?**  

**Оптимизация:**  
- Избегайте **O(n²)** и хуже для больших данных.  
- Используйте **хеш-таблицы** (`dict`, `set`) для поиска за `O(1)`.  
- Выбирайте **O(n log n)** вместо **O(n²)** (например, QuickSort вместо пузырьковой сортировки).  

**Когда можно не беспокоиться?**  
- Если `n` всегда маленькое (например, ≤ 100).  
- Если код выполняется однократно (не в цикле).

#### **7. Итог**  

📌 **О-нотация** — это язык, на котором говорят о производительности алгоритмов.  
📌 **Чем меньше сложность** — тем лучше (смотрите сводную таблицу).  
📌 **Правило большого пальца:**  
   - `O(1), O(log n), O(n)` — отлично!  
   - `O(n log n)` — приемлемо.  
   - `O(n²), O(2ⁿ), O(n!)` — опасно для больших `n`.  

**Дальнейшие шаги:**

- Изучать **амортизационный анализ** (например, для динамических массивов).  
- Разбирать **алгоритмы сортировки** (MergeSort, HeapSort).
