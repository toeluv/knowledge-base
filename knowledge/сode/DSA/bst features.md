# 🔍 **Важные свойства BST (Бинарного дерева поиска)**

## 📍 **Основные структурные свойства**

### **1. Минимальный элемент всегда слева**
- **Самый маленький элемент** находится в **крайнем левом узле**
- Чтобы найти минимальный элемент, нужно идти **всегда влево** до конца
- **Максимальный элемент** находится в **крайнем правом узле**

```java
// Поиск минимального элемента
TreeNode findMin(TreeNode root) {
    while (root.left != null) {
        root = root.left;
    }
    return root;
}

// Поиск максимального элемента  
TreeNode findMax(TreeNode root) {
    while (root.right != null) {
        root = root.right;
    }
    return root;
}
```

### **2. Упорядоченность значений**
- Для **любого узла X**:
  - **Все узлы в левом поддереве** < X
  - **Все узлы в правом поддереве** > X
- Это свойство **рекурсивно** выполняется для всех поддеревьев

### **3. In-order обход дает отсортированную последовательность**
```java
void inorder(TreeNode root) {
    if (root != null) {
        inorder(root.left);   // Сначала левое поддерево (меньшие)
        System.out.print(root.val + " ");  // Затем текущий узел
        inorder(root.right);  // Затем правое поддерево (большие)
    }
}
// Результат: элементы в возрастающем порядке
```

## 🔄 **Свойства наследования**

### **4. Родительские отношения**
- Если узел Y находится в **левом поддереве** X, то Y < X
- Если узел Y находится в **правом поддереве** X, то Y > X
- **Предок** всегда разделяет значения между левым и правым поддеревом

### **5. Свойство транзитивности**
- Если A < B и B < C, то A < C
- Это следует из упорядоченности дерева

## ⚡ **Операционные свойства**

### **6. Эффективность операций зависит от высоты**
- **В сбалансированном дереве** (высота ≈ log₂n):
  - Поиск: O(log n)
  - Вставка: O(log n) 
  - Удаление: O(log n)
- **В вырожденном дереве** (высота = n):
  - Все операции: O(n)

### **7. Уникальность значений**
- В **классическом BST** все значения уникальны
- При попытке вставить дубликат он игнорируется
- Можно модифицировать для хранения дубликатов (например, счетчиком)

## 🎯 **Свойства поиска**

### **8. Поиск всегда следует определенному пути**
- Сравниваем с корнем → идем влево/вправо → повторяем
- **Не нужно обходить все дерево** как в обычном бинарном дереве
- Путь поиска **детерминирован** (зависит только от значений)

### **9. Предшественник и преемник**
- **Predecessor** (предшественник) - наибольший элемент, меньший текущего
  - Если есть левое поддерево: max в левом поддереве
  - Если нет левого поддерева: первый предок, для которого текущий узел в правом поддереве
- **Successor** (преемник) - наименьший элемент, больший текущего
  - Если есть правое поддерево: min в правом поддереве
  - Если нет правого поддерева: первый предок, для которого текущий узел в левом поддереве

## 📊 **Геометрические свойства**

### **10. Форма зависит от порядка вставки**
- Одинаковые значения, вставленные в **разном порядке**, дают **разные деревья**
- **Отсортированная последовательность** дает вырожденное дерево (список)
- **Случайные значения** обычно дают сбалансированное дерево

### **11. Высота дерева**
- **Минимальная высота**: ⌊log₂n⌋ (полное дерево)
- **Максимальная высота**: n-1 (вырожденное дерево)
- **Средняя высота**: O(log n) для случайных данных

## 🔗 **Свойства связей**

### **12. Отсутствие циклов**
- BST является **ациклическим ориентированным графом**
- Нет обратных ссылок от потомков к предкам

### **13. Свойство потомков**
- Левый потомок < Родитель < Правый потомок
- Это свойство **сохраняется** при операциях вставки и удаления

## 💡 **Практические следствия**

### **14. Быстрая сортировка "на лету"**
- In-order обход сразу дает отсортированные данные
- Не нужно дополнительной сортировки

### **15. Диапазонные запросы эффективны**
- Можно быстро найти все элементы в диапазоне [min, max]
- Не нужно проверять все элементы

### **16. Ближайшие соседи**
- Можно эффективно найти элемент, ближайший к заданному значению
- Поиск предшественника и преемника помогает в этом

## ⚠️ **Важные ограничения**

### **17. Не гарантирует сбалансированность**
- BST может выродиться в связный список
- Для гарантированной балансировки нужны **AVL**, **Красно-черные** деревья

### **18. Зависимость от распределения данных**
- Эффективность сильно зависит от "случайности" входных данных
- Отсортированные данные дают худшую производительность

Эти свойства делают BST мощной структурой данных, но также показывают важность балансировки для поддержания эффективности!
