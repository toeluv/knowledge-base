## Магия префиксных сумм: от массивов к деревьям

### **Часть 1: Префиксные суммы в массивах**

**Задача**: найти количество подмассивов с суммой = k.

**Пример массива**: `[3, 4, -7, 3, 1, 3, 1, -4, -2, -2]`, `k = 7`

**Обычный подход**: O(N²) — перебираем все пары (i,j):
```python
count = 0
for i in range(n):
    for j in range(i, n):
        if sum(arr[i:j+1]) == k:
            count += 1
```

**Магия префиксных сумм**: O(N)  
Определяем префиксную сумму: `prefix[i] = sum(arr[0..i])`

**Ключевое наблюдение**:
```
sum(arr[i..j]) = prefix[j] - prefix[i-1]
```
Мы хотим `sum(arr[i..j]) = k`:
```
prefix[j] - prefix[i-1] = k
prefix[j] - k = prefix[i-1]
```

**Алгоритм**:
1. Идём по массиву, считаем текущую сумму `currSum`
2. Проверяем, встречалась ли ранее сумма `currSum - k`
3. Если да — столько подмассивов заканчивается в текущей позиции

**Пример для `[3, 4, 0, 7]`, `k = 7`**:

| Индекс | Значение | currSum | currSum-k | Что найдено                  |
|--------|----------|---------|-----------|------------------------------|
| 0      | 3        | 3       | -4        | —                            |
| 1      | 4        | 7       | 0         | Нашли! Подмассив [0..1] = [3,4] |
| 2      | 0        | 7       | 0         | Нашли! Подмассив [0..2] = [3,4,0] |
| 3      | 7        | 14      | 7         | Нашли! Подмассив [3..3] = [7] |

Map хранит: {0:1, 3:1, 7:2, 14:1}
- `currSum=7` → `7-k=0` → map[0]=1 путь
- `currSum=14` → `14-k=7` → map[7]=2 пути

### **Часть 2: Перенос на деревья**

**Дерево** — это как несколько путей из корня к листьям, но с общей историей.

**Аналогия**:
- В массиве: префиксная сумма от начала массива до i
- В дереве: префиксная сумма от корня до текущего узла

**Ключевое отличие**: в дереве есть **разветвление**, поэтому нужен backtracking.

---

### **Визуализация на дереве**

```
       10
      /  \
     5   -3
    / \    \
   3   2   11
```

**Цель**: найти пути с суммой 8.

**Путь от корня**: 10 → 5 → 3

1. **В узле 10**: currSum=10, нет 10-8=2 в map → 0 путей
2. **В узле 5**: currSum=15, нет 15-8=7 в map → 0 путей  
3. **В узле 3**: currSum=18, ищем 18-8=10 в map → map[10]=1 путь

**Какой путь нашли?**  
Путь от узла 10 до узла 3: 5+3=8  
Почему? Потому что:
- Префиксная сумма до 10: 10
- Префиксная сумма до 3: 18
- Разница: 18-10=8 → это сумма узлов после 10

---

### **Магия в коде**:

```java
// Проверяем, есть ли старый префикс, дающий нужную разницу
int count = prefix.getOrDefault(currSum - target, 0);
// currSum - oldPrefixSum = target
// значит путь от oldPrefixSum до текущего узла = target
```

**Почему backtracking?**
```
        A
       / \
      B   C
```
Когда обрабатываем левое поддерево (B), мы добавляем префиксы в map.  
При переходе к правому поддереву (C), эти префиксы не должны учитываться — путь не может идти от B к C через A.

---

### **Пример с backtracking**:

Обрабатываем узел B:
```
Map: {0:1, A:1, A+B:1}  // после B
```
После обработки всего поддерева B:
```
Map: {0:1, A:1}  // удалили A+B
```
Теперь обрабатываем C:
```
Map: {0:1, A:1, A+C:1}  // чистый лист!
```
Так мы учитываем только прямые пути сверху вниз.

---

### **Волшебная формула**:

```
Если currSum - oldSum = target,
то сумма на пути от oldSum до currSum = target
где:
- currSum = сумма от корня до текущего узла
- oldSum = сумма от корня до какого-то предка
```

**Map хранит**: "сколько раз встречалась сумма oldSum на пути от корня".

Каждый раз, когда мы находим `oldSum = currSum - target` в map, мы находим столько путей, сколько раз встречался этот oldSum, и все они заканчиваются в текущем узле.

---

### **Итог магии**:

1. **В массивах**: ищем `currSum - target` среди предыдущих префиксных сумм
2. **В деревьях**: то же самое, но с учётом древовидной структуры через backtracking
3. **Base case** `prefix.put(0,1)` — позволяет считать пути, начинающиеся с корня

Это превращает задачу O(N²) в O(N) — вот и вся магия!
