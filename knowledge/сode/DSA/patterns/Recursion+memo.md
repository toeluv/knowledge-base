## Суть задачи "Climbing Stairs"

**Проблема**: Сколько существует различных способов подняться по лестнице из n ступенек, если за один шаг можно подняться на 1 или 2 ступеньки.

**Пример для n = 3**:
```
1. 1 + 1 + 1
2. 1 + 2
3. 2 + 1
```
**Ответ**: 3 способа

## 1. Рекурсивное решение (ваш подход)

### Основная идея:
На каждой ступеньке у нас есть **два выбора**:
- Сделать шаг на 1 ступеньку
- Сделать шаг на 2 ступеньки

### Математическая формула:
```
climb(n) = climb(n-1) + climb(n-2)
```
Где:
- `climb(n-1)` - способы, если сначала шагнули на 1 ступеньку
- `climb(n-2)` - способы, если сначала шагнули на 2 ступеньки

### Базовые случаи:
- `climb(0) = 1` - мы уже на вершине (1 способ)
- `climb(-1) = 0` - перешагнули вершину (0 способов)

```java
public int climbStairs(int n) {
    return climbRecursive(0, n);
}

private int climbRecursive(int currentStair, int total) {
    // Перешагнули вершину - невалидный путь
    if (currentStair > total) {
        return 0;
    }
    // Достигли вершины - нашли один валидный путь
    if (currentStair == total) {
        return 1;
    }
    // Рекурсивно пробуем оба варианта
    return climbRecursive(currentStair + 1, total) + climbRecursive(currentStair + 2, total);
}
```

### Проблема рекурсивного подхода:
Дерево вызовов для n=5:
```
climb(0,5)
├── climb(1,5)
│   ├── climb(2,5)  ← вычисляется многократно!
│   └── climb(3,5)
└── climb(2,5)      ← вычисляется многократно!
    ├── climb(3,5)  ← вычисляется многократно!
    └── climb(4,5)
```

**Одинаковые подзадачи вычисляются много раз!**

## 2. Решение с мемоизацией

### Основная идея мемоизации:
**"Запоминаем" результаты вычислений**, чтобы не пересчитывать их повторно.

### Как работает:
1. Создаем массив для хранения результатов (`memo`)
2. При первом вычислении `climb(k)` сохраняем результат в `memo[k]`
3. При повторном запросе `climb(k)` возвращаем сохраненное значение

```java
public int climbStairs(int n) {
    // Массив для запоминания результатов
    int[] memo = new int[n + 1];
    return climbMemo(0, n, memo);
}

private int climbMemo(int current, int total, int[] memo) {
    // Перешагнули вершину
    if (current > total) return 0;
    
    // Достигли вершины
    if (current == total) return 1;
    
    // Если уже вычисляли эту подзадачу - возвращаем сохраненный результат
    if (memo[current] > 0) return memo[current];
    
    // Вычисляем и сохраняем результат
    memo[current] = climbMemo(current + 1, total, memo) + climbMemo(current + 2, total, memo);
    return memo[current];
}
```

### Визуализация мемоизации для n=5:

```
climb(0,5)
├── climb(1,5) → вычисляем, сохраняем memo[1]=8
├── climb(2,5) → вычисляем, сохраняем memo[2]=5
└── ...

При повторных вызовах:
climb(2,5) → берем из memo[2]=5 (без вычислений!)
```

## Сравнение на примере n=5

### Без мемоизации:
```
climb(0,5)
├── climb(1,5)
│   ├── climb(2,5)
│   │   ├── climb(3,5)
│   │   │   ├── climb(4,5)
│   │   │   │   ├── climb(5,5) ✓
│   │   │   │   └── climb(6,5) ✗
│   │   │   └── climb(5,5) ✓
│   │   └── climb(4,5) ← вычисляется повторно!
│   └── climb(3,5) ← вычисляется повторно!
└── climb(2,5) ← вычисляется повторно!
```
**Всего вызовов: 15**

### С мемоизацией:
```
climb(0,5)
├── climb(1,5) → вычисляем, сохраняем
├── climb(2,5) → вычисляем, сохраняем
└── ...

climb(2,5) → используем сохраненное значение
climb(3,5) → используем сохраненное значение
```
**Всего вызовов: 6**

## Ключевые отличия

| Аспект | Рекурсия | Мемоизация |
|--------|----------|------------|
| **Сложность** | O(2ⁿ) | O(n) |
| **Память** | O(n) | O(n) |
| **Вычисления** | Многократные | Однократные |
| **n=40** | ~200 млн вызовов | ~40 вызовов |
| **Время** | Минуты | Миллисекунды |

## Почему мемоизация работает так хорошо?

Потому что задача обладает **свойством оптимальной подструктуры**:
- Большая задача разбивается на меньшие подзадачи
- Подзадачи **перекрываются** (повторяются)
- Решения подзадач можно **комбинировать**

Мемоизация устраняет главную проблему "наивной" рекурсии - **избыточные вычисления**.

Это классический пример преобразования неэффективного алгоритма в эффективный с помощью динамического программирования!
