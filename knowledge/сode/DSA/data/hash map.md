### Реализация HashMap в Java

#### 1. Основные характеристики HashMap
- **Хеш-таблица**: Реализация интерфейса Map на основе массива бакетов
- **Разрешение коллизий**: Метод цепочек (связные списки в каждом бакете)
- **Динамическое расширение**: Увеличивает размер при достижении порога загрузки

#### 2. Сложность операций (в среднем случае)

Операция | Сложность | Примечания
---|---|---
Добавление (put) | O(1) | Может деградировать до O(n) при коллизиях
Получение (get) | O(1) | Зависит от равномерности хеш-функции
Удаление (remove) | O(1) | Аналогично get
Поиск ключа (containsKey) | O(1) | Зависит от распределения хешей
Поиск значения (containsValue) | O(n) | Требует полного перебора

#### 3. Внутренняя структура

**1. Узел (Node)**:
```java
static class Node<K,V> {
    final int hash;
    final K key;
    V value;
    Node<K,V> next; // Для разрешения коллизий
}
```

**2. Основные поля**:
- `Node<K,V>[] buckets`: Массив бакетов (корзин)
- `int size`: Количество элементов
- `float loadFactor`: Коэффициент загрузки (по умолчанию 0.75)
- `int threshold`: Порог расширения (capacity * loadFactor)

#### 4. Ключевые механизмы

**1. Хеширование**:
```java
(key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
```
- Нулевой ключ всегда попадает в бакет 0
- Дополнительное смешивание битов для лучшего распределения

**2. Определение индекса**:
```java
(n - 1) & hash // n - размер массива бакетов
```

**3. Разрешение коллизий**:
- Метод цепочек (chaining)
- При достижении длины цепочки 8 преобразуется в сбалансированное дерево (в стандартной реализации)

#### 5. Процесс добавления элемента

1. Вычисление хеша ключа
2. Определение индекса бакета
3. Поиск в цепочке:
   - Если ключ существует - обновление значения
   - Если нет - добавление нового узла
4. Проверка необходимости расширения

#### 6. Динамическое расширение (resize)

1. Увеличение размера в 2 раза
2. Перераспределение элементов:
   - Новый индекс = hash & (newCap - 1)
   - Элементы либо остаются на месте, либо смещаются на старый размер

#### 7. Особенности реализации

**1. Итераторы**:
- Fail-fast: бросают ConcurrentModificationException при изменении во время итерации
- Не гарантируют порядок элементов

**2. View-коллекции**:
- `keySet()`, `values()`, `entrySet()` возвращают представления
- Изменения в view отражаются в основной мапе и наоборот

**3. Оптимизации**:
- Кэширование хеш-кодов
- Ленивая инициализация view-коллекций
- Специальная обработка null-ключей

#### 8. Сравнение с другими структурами

Характеристика | HashMap | TreeMap | LinkedHashMap
---|---|---|---
Сложность операций | O(1) | O(log n) | O(1)
Порядок элементов | Не гарантирован | Сортировка по ключам | В порядке добавления
Нулевые ключи | Разрешены | Запрещены (если нет компаратора) | Разрешены
Память | Средняя | Высокая | Высокая

#### 9. Рекомендации по использованию

1. **Выбор начальных параметров**:
```java
// Если ожидается ~100 элементов:
new HashMap<>(133, 0.75f); // 100 / 0.75 = ~133
```

2. **Ключи должны иметь**:
- Корректные hashCode() и equals()
- Неизменяемые поля, участвующие в хешировании

3. **Альтернативы**:
- LinkedHashMap: если важен порядок добавления
- TreeMap: если нужна сортировка
- ConcurrentHashMap: для многопоточного доступа

#### 10. Пример использования
```java
Map<String, Integer> map = new HashMap<>();
map.put("apple", 1); 
map.put("banana", 2);

// Быстрый доступ
Integer count = map.get("apple"); // O(1)

// Итерация (порядок не гарантирован)
map.forEach((k, v) -> System.out.println(k + ": " + v));
```

#### 11. Производительность
- **Лучшие показатели** при равномерном распределении хешей
- **Деградация** при большом количестве коллизий
- **Оптимальная загрузка**: 0.75 (баланс между памятью и производительностью)

Эта реализация обеспечивает оптимальный баланс между скоростью операций и потреблением памяти для большинства сценариев использования.
