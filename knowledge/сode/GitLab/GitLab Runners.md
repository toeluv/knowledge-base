## GitLab Runners

**Важно:** "Хост-машина" в данном контексте может быть физическим сервером, виртуальной машиной (VM), контейнером, или даже кластером Kubernetes. Главное, что GitLab Runner должен быть установлен и работать где-то, чтобы выполнять задачи CI/CD.

**1. Прямая установка (Direct Installation):**

*   **Описание:** GitLab Runner устанавливается непосредственно на операционную систему хост-машины. Это включает в себя скачивание и установку бинарного файла GitLab Runner, либо использование пакетного менеджера (например, `apt`, `yum`, `brew` и т.д.) для установки.
*   **Преимущества:** Простота установки (особенно для `shell` executor), полный контроль над хост-машиной, потенциально более высокая производительность (из-за отсутствия дополнительной виртуализации или контейнеризации).
*   **Недостатки:** Отсутствие изоляции между job'ами (если используется `shell` executor), потенциальные конфликты зависимостей, сложность масштабирования.  Требует ручной настройки и обслуживания.
*   **Подходящие Executors:** `shell`, `virtualbox`, `ssh`, `custom`.
*   **Схема:**

    ```
    +-----------------------------+
    | Хост-машина                 |
    | (Linux, Windows, macOS)     |
    +-----------------------------+
    |   GitLab Runner             |
    |   (установлен напрямую)     |
    |   +---------------------+   |
    |   |  Executor: Shell   |    |
    |   |  Executor: SSH     |    |
    |   |Executor: VirtualBox|    |
    |   |  Executor: Custom  |    |
    |   +---------------------+   |
    +-----------------------------+
    ```

    *   **Пример установки (Linux):**

        ```bash
        # Скачать бинарный файл
        sudo wget -O /usr/local/bin/gitlab-runner https://gitlab-runner-downloads.s3.amazonaws.com/latest/binaries/gitlab-runner-linux-amd64
        # Сделать исполняемым
        sudo chmod +x /usr/local/bin/gitlab-runner
        # Создать пользователя gitlab-runner
        sudo useradd -M -s /bin/bash gitlab-runner
        # Установить как сервис
        sudo gitlab-runner install --user=gitlab-runner --working-directory=/home/gitlab-runner
        # Запустить сервис
        sudo gitlab-runner start
        ```

**2. Установка через Docker Container:**

*   **Описание:** GitLab Runner запускается внутри Docker-контейнера. Это обеспечивает изоляцию Runner от основной системы, упрощает обновление и обслуживание.
*   **Преимущества:** Изоляция, воспроизводимость, простота обновления, портативность.  Относительно легко настроить.
*   **Недостатки:** Небольшие накладные расходы на контейнеризацию, необходимость наличия Docker Engine на хост-машине, сложнее настроить доступ к специфическим ресурсам хоста (например, USB-устройствам).  Если нужно использовать `shell` executor, нужно пробрасывать socket docker.
*   **Подходящие Executors:** `docker`, `shell` (с оговорками), `ssh` (с оговорками).
*   **Схема:**

    ```
    +-----------------------------+
    | Хост-машина                   |
    | (Linux, Windows, macOS)       |
    +-----------------------------+
    |   Docker Engine               |
    |   +---------------------+     |
    |   | GitLab Runner        |    |
    |   | (Docker Container)   |    |
    |   |   +---------------+  |    |
    |   |   |  Executor:     | |    |
    |   |   |   Docker       | |    |
    |   |   |   Shell        | |    |
    |   |   |   SSH          | |    |
    |   |   +---------------+  |    |
    |   +---------------------+     |
    +-----------------------------+
    ```

    *   **Пример установки:**

        ```bash
        # Запустить контейнер
        docker run -d --name gitlab-runner --restart always \
          -v /srv/gitlab-runner/config:/etc/gitlab-runner \
          -v /var/run/docker.sock:/var/run/docker.sock \
          gitlab/gitlab-runner:latest
        ```
        * Важно: проброска `/var/run/docker.sock` дает доступ к Docker хоста (DooD). Используйте осторожно или рассмотрите DinD.

**3. Установка через Kubernetes:**

*   **Описание:** GitLab Runner устанавливается как Deployment или Pod в Kubernetes кластере. Это позволяет масштабировать Runner'ы, управлять ими централизованно, и использовать ресурсы Kubernetes для выполнения задач CI/CD.
*   **Преимущества:** Масштабируемость, отказоустойчивость, интеграция с Kubernetes, динамическое выделение ресурсов.
*   **Недостатки:** Самый сложный в настройке, требует Kubernetes кластер, знание Kubernetes.
*   **Подходящие Executors:** `kubernetes`.
*   **Схема:**

    ```
    +-----------------------------+
    | Kubernetes Cluster          |
    +-----------------------------+
    |   +---------------------+    |
    |   | GitLab Runner       |    |
    |   | (Deployment/Pod)    |    |
    |   |   +---------------+ |    |
    |   |   |  Executor:    | |    |
    |   |   |   Kubernetes  | |    |
    |   |   +---------------+ |    |
    |   +---------------------+    |
    +-----------------------------+
    ```

    *   **Пример установки (Helm):**

        ```bash
        # Добавить репозиторий GitLab Helm
        helm repo add gitlab https://charts.gitlab.io
        # Обновить репозитории
        helm repo update
        # Установить GitLab Runner
        helm install gitlab-runner gitlab/gitlab-runner \
          --set gitlabUrl=https://gitlab.example.com/ \
          --set runnerRegistrationToken=YOUR_REGISTRATION_TOKEN
        ```
        Замените `https://gitlab.example.com/` и `YOUR_REGISTRATION_TOKEN` на ваши значения.  Для продвинутой настройки используйте файл `values.yaml`.

**Выбор подходящего типа установки:**

*   **Для простых проектов и тестирования:** Прямая установка с `shell` executor'ом может быть достаточной.
*   **Для проектов, требующих изоляции и воспроизводимости:** Установка через Docker с `docker` executor'ом - хороший выбор.
*   **Для крупных проектов с высокими требованиями к масштабируемости и отказоустойчивости:** Установка через Kubernetes с `kubernetes` executor'ом - наиболее подходящий вариант.

Надеюсь, эти схемы и объяснения помогут вам лучше понять различные способы установки GitLab Runner!
