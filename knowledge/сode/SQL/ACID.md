# **ACID: принципы надежных транзакций в БД**  

**ACID** — это набор свойств, гарантирующих корректность выполнения транзакций в базах данных.  

## **1. Atomicity (Атомарность)**  
**«Все или ничего»**  
- Транзакция выполняется **целиком** либо **не выполняется вообще**.  
- Если что-то пошло не так (ошибка, сбой), все изменения **откатываются** (ROLLBACK).  

**Пример**:  
```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE user_id = 1;
UPDATE accounts SET balance = balance + 100 WHERE user_id = 2;
-- Если вторая команда упадет, первая тоже отменится
COMMIT; -- или ROLLBACK при ошибке
```  

## **2. Consistency (Согласованность)**  
**«Данные всегда в валидном состоянии»**  
- Транзакция переводит БД **из одного корректного состояния в другое**.  
- Ограничения (CHECK, FOREIGN KEY, UNIQUE) **не могут быть нарушены**.  

**Пример**:  
```sql
-- Если в таблице есть CHECK (balance >= 0), то:
UPDATE accounts SET balance = -100 WHERE user_id = 1; -- Ошибка, транзакция откатится
```  

## **3. Isolation (Изолированность)**  
**«Транзакции не мешают друг другу»**  
- Параллельные транзакции **не должны влиять** на результат друг друга.  
- Реализуется через **блокировки** или **MVCC** (Multiversion Concurrency Control).  

**Проблемы без изоляции**:  
- **Грязное чтение** (Dirty Read) – чтение незакоммиченных данных.  
- **Неповторяемое чтение** (Non-repeatable Read) – данные изменились между запросами.  
- **Фантомы** (Phantom Read) – появление новых строк между запросами.  

**Уровни изоляции**:  
| Уровень              | Dirty Read | Non-repeatable Read | Phantom Read |  
|----------------------|------------|----------------------|--------------|  
| **Read Uncommitted** | ✅ Да       | ✅ Да                 | ✅ Да         |  
| **Read Committed**   | ❌ Нет      | ✅ Да                 | ✅ Да         |  
| **Repeatable Read**  | ❌ Нет      | ❌ Нет                | ✅ Да         |  
| **Serializable**     | ❌ Нет      | ❌ Нет                | ❌ Нет        |  

## **4. Durability (Долговечность)**  
**«Если транзакция завершилась, данные не пропадут»**  
- После `COMMIT` изменения **гарантированно сохраняются**, даже при сбое (например, отключении сервера).  
- Обеспечивается через **журнал транзакций (WAL — Write-Ahead Log)**.  

**Пример**:  
```sql
COMMIT; -- Данные записаны на диск, даже если сервер упадет через секунду
```  

## **Итог**  
- **Atomicity** → Откатывает при ошибках.  
- **Consistency** → Следит за правилами БД.  
- **Isolation** → Контролирует параллельный доступ.  
- **Durability** → Гарантирует сохранность данных.  

Без ACID транзакции были бы ненадежными, а данные — несогласованными. 🚀
