Структура сетевого сообщения (пакета) различается на разных уровнях модели OSI или TCP/IP. Каждый уровень добавляет свою служебную информацию (заголовки), формируя инкапсуляцию данных.  

---

## **1. Модель OSI vs TCP/IP**

| **Уровень OSI**       | **Уровень TCP/IP**       | Примеры протоколов          |
|-----------------------|-------------------------|----------------------------|
| 7. Прикладной         |                         | HTTP, FTP, DNS, SMTP       |

| 5. Сеансовый          |                         | NetBIOS, RPC               |

---

## **2. Структура сообщения на разных уровнях**  

### **🔹 1. Прикладной уровень (HTTP, FTP, DNS и др.)**  
Сообщение содержит "чистые" данные (например, HTTP-запрос или email).  

**Пример HTTP-запроса:**  
```
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
```
*(Этот текст передаётся на транспортный уровень для упаковки в сегмент TCP.)*  

---

### **🔹 2. Транспортный уровень (TCP / UDP)**  
Добавляет заголовок с портами и контрольной суммой.  

#### **TCP-сегмент:**  
```
| TCP Header | Данные (HTTP-запрос) |
```
**Структура TCP-заголовка (20+ байт):**  
- Порт источника (2 байта)  
- Порт назначения (2 байта)  
- Номер последовательности (4 байта)  
- Номер подтверждения (4 байта)  
- Флаги (SYN, ACK, FIN и др.)  
- Контрольная сумма (2 байта)  

#### **UDP-датаграмма (более простая):**  
```
| UDP Header | Данные (DNS-запрос) |
```
**Структура UDP-заголовка (8 байт):**  
- Порт источника  
- Порт назначения  
- Длина  
- Контрольная сумма  

---

### **🔹 3. Сетевой уровень (IP)**  
Добавляет IP-адреса источника и назначения.  

#### **IP-пакет:**  
```
| IP Header | TCP/UDP-сегмент |
```
**Структура IP-заголовка (20+ байт):**  
- Версия (IPv4/IPv6)  
- Длина заголовка  
- TTL (время жизни)  
- Протокол (TCP=6, UDP=17)  
- IP источника (4 байта для IPv4, 16 для IPv6)  
- IP назначения  
- Контрольная сумма  

---

### **🔹 4. Канальный уровень (Ethernet, Wi-Fi)**  
Добавляет MAC-адреса и контрольную сумму (FCS).  

#### **Ethernet-кадр:**  
```
| MAC-адрес получателя | MAC-адрес отправителя | Тип (IPv4/IPv6) | IP-пакет | FCS |
```
**Структура Ethernet-кадра:**  
- **MAC назначения** (6 байт)  
- **MAC источника** (6 байт)  
- **Тип** (0x0800 для IPv4, 0x86DD для IPv6)  
- **Данные (IP-пакет)**  
- **FCS** (контрольная сумма, 4 байта)  

*(В Wi-Fi структура сложнее, добавляются QoS, управляющие флаги и др.)*  

---

### **🔹 5. Физический уровень (биты в кабель/радиоволны)**  
Данные превращаются в электрические/оптические/радиосигналы.  

- Ethernet: **Манчестерское кодирование**, **NRZ**  
- Wi-Fi: **OFDM**, **QAM-модуляция**  
- Оптоволокно: **Импульсы света**  

---

## **3. Пример полной инкапсуляции (HTTP → TCP → IP → Ethernet)**  
```
[ Ethernet Header ][ IP Header ][ TCP Header ][ HTTP-запрос ][ FCS ]
```
1. **HTTP**: `GET /index.html`  
2. **TCP**: Добавляет порты (например, 80) и контрольную сумму.  
3. **IP**: Добавляет IP-адреса (например, 192.168.1.1 → 8.8.8.8).  
4. **Ethernet**: Добавляет MAC-адреса (например, `AA:BB:CC:DD:EE:FF → 11:22:33:44:55:66`).  
5. **Физический уровень**: Передаёт биты по проводу/воздуху.  

---

## **4. Размеры заголовков (в байтах)**  
| Уровень       | TCP  | UDP  | IPv4 | IPv6 | Ethernet |
|--------------|------|------|------|------|----------|
| Заголовок    | 20+  | 8    | 20+  | 40   | 14       |
| Макс. полезная нагрузка | ~1460 (MTU) | ~1472 | До 65535 | До 65535 | До 1500 (стандарт) |

*(MTU — Maximum Transmission Unit, обычно 1500 байт для Ethernet.)*  

---

## **Вывод**  
- Каждый уровень добавляет свой заголовок, формируя "матрешку" данных.  
- Чем ниже уровень, тем ближе к физической передаче.  
- TCP надежный (есть подтверждение), UDP — быстрый (без гарантий).  
- Ethernet работает с MAC-адресами, IP — с IP-адресами.
