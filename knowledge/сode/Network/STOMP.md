## STOMP (Simple Text Oriented Messaging Protocol)

Протокол STOMP (Simple Text Oriented Messaging Protocol) - простой текстовый протокол обмена сообщениями. Обеспечивает интероперабельность между различными месседж-брокерами и клиентами, написанными на разных языках, но не определяет как брокер обрабатывает сообщения внутри, а только формат обмена данными между клиентом и брокером.

**Ключевые особенности:**

*   **Текстовый протокол:** Легко читаемый и отлаживаемый.
*   **Простой:** Легко реализовать как на стороне клиента, так и на стороне сервера.
*   **Ориентирован на сообщения:** Основан на обмене текстовыми сообщениями.
*   **Независимый от транспорта:** Работает поверх различных транспортных протоколов (например, TCP, WebSocket).
*   **Основан на командах (verbs):**  Использует предопределенный набор команд.
*   **Использует заголовки (headers):** Метаданные, описывающие сообщение.
*   **Направления обмена сообщениями:**
    *   От клиента к брокеру (например, `SEND`, `SUBSCRIBE`, `UNSUBSCRIBE`, `CONNECT`, `DISCONNECT`)
    *   От брокера к клиенту (например, `MESSAGE`, `CONNECTED`, `ERROR`)

**Основные компоненты:**

*   **Клиент:**  Приложение, отправляющее и/или принимающее сообщения.
*   **Брокер (Message Broker):**  Промежуточный сервер, маршрутизирующий сообщения между клиентами.
*   **Назначение (Destination):**  Идентификатор, указывающий, куда отправлять или откуда получать сообщения (например, очередь или тема).

**Основные команды (verbs):**

| Команда    | Направление | Описание                                                                |
|------------|-------------|--------------------------------------------------------------------------|
| `CONNECT`  | C -> S      | Устанавливает соединение с брокером.                                  |
| `CONNECTED`| S -> C      | Подтверждает успешное соединение.                                     |
| `SEND`     | C -> S      | Отправляет сообщение в указанное назначение.                            |
| `SUBSCRIBE`| C -> S      | Подписывается на получение сообщений из указанного назначения.         |
| `UNSUBSCRIBE`| C -> S    | Отписывается от получения сообщений из указанного назначения.        |
| `BEGIN`    | C -> S      | Начинает транзакцию.                                                |
| `COMMIT`   | C -> S      | Фиксирует транзакцию.                                               |
| `ABORT`    | C -> S      | Отменяет транзакцию.                                                 |
| `ACK`      | C -> S      | Подтверждает получение сообщения.                                    |
| `NACK`     | C -> S      | Отрицательно подтверждает получение сообщения (требует повторной отправки). |
| `DISCONNECT`| C -> S    | Закрывает соединение с брокером.                                   |
| `MESSAGE`  | S -> C      | Отправляет сообщение клиенту, подписанному на назначение.              |
| `ERROR`    | S -> C      | Отправляет сообщение об ошибке.                                     |

**Структура сообщения STOMP:**

```
COMMAND
header1:value1
header2:value2

Body of the message
```

*   **`COMMAND`**: Одна из команд STOMP (например, `SEND`, `MESSAGE`, `ERROR`).
*   **`header1:value1 ... headerN:valueN`**: Заголовки сообщения.  Каждая строка содержит имя заголовка и его значение, разделенные двоеточием.
*   **`Body of the message`**:  Необязательное тело сообщения (может быть пустым).

**Пример:**

Отправка сообщения клиентом брокеру:

```
SEND
destination:/queue/my-queue
content-type:text/plain

Hello, STOMP!
```

Получение сообщения брокером клиенту:

```
MESSAGE
message-id:12345
destination:/queue/my-queue
content-type:text/plain

Hello, STOMP!
```

**Преимущества:**

*   **Простота:** Легко понять и реализовать.
*   **Интероперабельность:** Позволяет взаимодействовать с различными месседж-брокерами.
*   **Гибкость:** Поддерживает различные транспортные протоколы.
*   **Транзакционность:** Поддерживает транзакции для обеспечения надежности.

**Недостатки:**

*   **Ограниченная функциональность:**  По сравнению с более сложными протоколами, такими как AMQP.
*   **Текстовый формат:** Менее эффективен, чем бинарные протоколы.
*   **Меньшая производительность:**  Из-за текстового формата и обработки заголовков.

**Типичные сценарии использования:**

*   Обмен сообщениями между веб-сервером и клиентскими приложениями (например, чат, уведомления).
*   Интеграция различных приложений с помощью месседж-брокера.
*   Реализация паттерна Publisher-Subscriber.
*   Использование в связке с WebSocket для создания интерактивных веб-приложений.

**Заключение:**

STOMP - это простой и эффективный протокол для обмена сообщениями, который особенно полезен для интеграции различных систем и создания интерактивных веб-приложений.  Хотя он и не обладает всей функциональностью более сложных протоколов, его простота делает его привлекательным вариантом для многих сценариев.
