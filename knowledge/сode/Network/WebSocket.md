## WebSocket
WebSocket - это коммуникационный протокол, который обеспечивает **полнодуплексную** связь между клиентом (например, браузером) и сервером по **одному TCP-соединению**. В отличие от HTTP, где клиент отправляет запрос, сервер отвечает, и соединение закрывается (или остаётся открытым при использовании Keep-Alive), WebSocket позволяет обеим сторонам отправлять данные друг другу в любой момент времени, пока соединение активно.

Вот упрощенное объяснение того, как работает WebSocket:
```
+-------------------+                               +-------------------+
|                   |                               |                   |
|    Клиент         |                               |    Сервер         |
|                   |                               |                   |
+-------------------+                               +-------------------+
         |                                                  |
         | HTTP-запрос с Upgrade: WebSocket               |
         |------------------------------------------------>|
         |                                                  |
         | HTTP 101 Switching Protocols (успешное обновление)|
         |<------------------------------------------------|
         |                                                  |
         | WebSocket-соединение установлено                 |
         |==================================================|
         |                                                  |
         | Двусторонний обмен данными (frames)              |
         |<------------------------------------------------>|
         |                                                  |
         | Закрытие соединения (Close frame)               |
         |<------------------------------------------------>|
         |                                                  |
```
**1. Установка соединения (WebSocket Handshake):**

*   **HTTP Upgrade:**  Клиент начинает с HTTP-запроса, содержащего заголовок `Upgrade: websocket`. Этот заголовок сообщает серверу, что клиент хочет установить WebSocket-соединение.
*   **Sec-WebSocket-Key:**  В запросе также присутствует заголовок `Sec-WebSocket-Key` содержащий случайную строку, закодированную в Base64. Этот ключ используется для предотвращения случайного или злонамеренного установления WebSocket-соединения.
*   **Sec-WebSocket-Version:**  Этот заголовок указывает версию WebSocket протокола, которую поддерживает клиент.
*   **Серверный ответ:** Если сервер поддерживает WebSocket и принимает запрос, он отвечает HTTP-ответом с кодом `101 Switching Protocols`.  Этот ответ содержит заголовок `Upgrade: websocket` и `Connection: Upgrade`, подтверждающие переключение протокола.
*   **Sec-WebSocket-Accept:** Самое важное в ответе - это заголовок `Sec-WebSocket-Accept`.  Сервер берет `Sec-WebSocket-Key` из запроса клиента, добавляет к нему фиксированную строку `258EAFA5-E914-47DA-95CA-C5AB0DC85B11`, хэширует результат алгоритмом SHA-1, кодирует его в Base64 и отправляет в заголовке `Sec-WebSocket-Accept`.  Клиент может проверить этот заголовок, чтобы убедиться, что сервер правильно обработал запрос и действительно поддерживает WebSocket.

**2. Полнодуплексная связь:**

*   **После успешного "рукопожатия"** устанавливается постоянное WebSocket-соединение.
*   **Фреймы данных:** Данные передаются между клиентом и сервером в виде *фреймов*.  Фрейм WebSocket состоит из заголовка и полезной нагрузки (данных).  Заголовок содержит информацию о типе фрейма (текстовый, бинарный, управляющий) и длине полезной нагрузки.
*   **Асинхронная передача:** Обе стороны могут отправлять и получать фреймы данных в любой момент времени, не дожидаясь запроса от другой стороны. Это позволяет реализовать мгновенное обновление данных и двусторонние приложения реального времени.

**3. Закрытие соединения:**

*   **Управляющие фреймы:** Закрытие WebSocket-соединения также осуществляется с помощью управляющих фреймов.
*   **Закрывающий фрейм:** Одна из сторон отправляет фрейм типа "close" (код `0x88`) с кодом состояния закрытия и опциональным сообщением.
*   **Подтверждение закрытия:** Другая сторона отвечает фреймом типа "close" с тем же кодом состояния и сообщением (или с кодом состояния `1000` - "Normal Closure", если сообщение не было получено).
*   **Соединение закрывается:** После обмена закрывающими фреймами TCP-соединение закрывается.

**Ключевые особенности и преимущества WebSocket:**

*   **Полнодуплексность:**  Возможность обмена данными в обоих направлениях одновременно, что значительно улучшает производительность для приложений реального времени.
*   **Постоянное соединение:**  Устраняет необходимость в повторных запросах и ответах, как в HTTP, что снижает накладные расходы и задержки.
*   **Низкая задержка:**  Идеально подходит для приложений, требующих мгновенного обновления данных, таких как онлайн-игры, чаты, биржевые платформы и инструменты совместной работы.
*   **Бинарная поддержка:**  Позволяет передавать не только текстовые данные, но и бинарные данные, что полезно для передачи мультимедийных файлов и других форматов данных.
*   **Использование одного TCP-соединения:**  Уменьшает нагрузку на сервер и сеть.
*   **Совместимость с прокси и межсетевыми экранами:** WebSocket разработан для работы через большинство стандартных сетевых инфраструктур.

**Примеры использования:**

*   **Чат-приложения:** Мгновенная отправка и получение сообщений.
*   **Онлайн-игры:** Обновление информации об игроках, объектах и событиях в реальном времени.
*   **Финансовые приложения:**  Трансляция котировок акций, валютных курсов и других финансовых данных в реальном времени.
*   **Социальные сети:**  Обновление ленты новостей, уведомлений и статусов в реальном времени.
*   **Инструменты совместной работы:**  Редактирование документов в реальном времени, совместный просмотр и аннотирование.
*   **Системы мониторинга:**  Визуализация данных датчиков и метрик в реальном времени.

**Сравнение с HTTP:**

| Характеристика | HTTP | WebSocket |
|---|---|---|
| Тип связи | Полудуплекс (запрос-ответ) | Полнодуплекс |
| Соединение | Без сохранения состояния (stateless) | С сохранением состояния (stateful) |
| Тип протокола | Текстовый | Фреймовый |
| Задержка | Высокая | Низкая |
| Накладные расходы | Высокие (повторные запросы) | Низкие (одно соединение) |
| Идеально подходит для | Загрузка веб-страниц, статичного контента | Приложения реального времени, двусторонние коммуникации |

**Заключение:**

WebSocket - мощный протокол для создания интерактивных и отзывчивых веб-приложений, требующих двусторонней связи в реальном времени. Он обеспечивает низкую задержку, высокую производительность и эффективное использование ресурсов.  Однако стоит помнить, что для простых задач, где обновления происходят нечасто, обычный HTTP может быть вполне достаточным и более простым в реализации.
