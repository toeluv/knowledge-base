### Конспект по ключевым концепциям Domain-Driven Design (DDD)

---

#### **1. Основные строительные блоки**
| Концепция               | Описание                                                                 | Примеры                     |
|-------------------------|--------------------------------------------------------------------------|-----------------------------|
| **Value Object**        | Неизменяемый объект без идентификатора, определяется атрибутами          | Дата, денежная сумма, координаты |
| **Domain Entity**       | Объект с уникальным ID и жизненным циклом                                | Пользователь, заказ, продукт |
| **Aggregate Root**      | Главная сущность, управляющая группой связанных объектов                 | Заказ (с элементами заказа) |

---

#### **2. Организация домена**
| Концепция               | Характеристики                                                           | Применение                  |
|-------------------------|--------------------------------------------------------------------------|-----------------------------|
| **Bounded Context**     | Четкие границы доменной модели с унифицированными правилами              | Контексты "Продажи" и "Доставка" |
| **Ubiquitous Language** | Общий язык для команды и кода                                            | Термин "Заказ" везде одинаков |
| **Context Map**         | Диаграмма связей между контекстами                                       | Взаимодействие "Продажи" ↔ "Доставка" |

---

#### **3. Паттерны работы с данными**
| Концепция               | Принцип                                                                  | Пример использования        |
|-------------------------|--------------------------------------------------------------------------|-----------------------------|
| **Repository**          | Абстракция для доступа к данным                                          | `OrderRepository` для заказов |
| **Factory**             | Инкапсуляция логики создания сложных объектов                            | `OrderFactory`              |
| **Specification**       | Инкапсуляция бизнес-правил                                               | `IsPremiumCustomer`         |

---

#### **4. События и интеграция**
| Концепция               | Роль                                                                     | Пример                      |
|-------------------------|--------------------------------------------------------------------------|-----------------------------|
| **Domain Event**        | Фиксация значимых изменений в домене                                     | Событие `OrderPlaced`       |
| **Anti-Corruption Layer** | Изоляция домена от внешних систем                                       | Адаптер для внешнего API    |

---

#### **5. Продвинутые архитектурные подходы**
| Концепция               | Описание                                                                 | Преимущества                |
|-------------------------|--------------------------------------------------------------------------|-----------------------------|
| **CQRS**                | Разделение операций: команды (изменение) и запросы (чтение)              | Отдельные модели для отчетов и изменений |
| **Event Sourcing**      | Хранение истории событий вместо текущего состояния                       | Аудит, восстановление состояния |

---

#### **6. Уровни проектирования**
| Тип проектирования      | Фокус                                                                    | Инструменты                 |
|-------------------------|--------------------------------------------------------------------------|-----------------------------|
| **Strategic Design**    | Организация домена на высоком уровне                                     | Bounded Context, Context Map |
| **Tactical Design**     | Реализация деталей модели                                                | Entity, Aggregate, Value Object |

---

### Ключевые принципы:
1. **Изоляция контекстов**: Каждый Bounded Context имеет свою модель.
2. **Единый язык**: Термины одинаковы в коде, документации и обсуждениях.
3. **Инварианты агрегатов**: Aggregate Root гарантирует целостность данных.
4. **События как история**: Event Sourcing сохраняет все изменения.

---

### Когда что использовать:
- **Value Object** → Для неизменяемых данных без идентичности (координаты).
- **Aggregate Root** → Для управления сложными связями (заказ с позициями).
- **CQRS** → Когда нагрузка на чтение и запись сильно различается.
- **Anti-Corruption Layer** → При интеграции с устаревшими системами.

Этот конспект охватывает ключевые аспекты DDD для проектирования сложных бизнес-систем.
