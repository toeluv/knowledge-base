# Правила написания RESTful API эндпоинтов

## 1. Используйте существительные, а не глаголы
Эндпоинты должны отражать ресурсы, а не действия.  
**Пример**:  
- ❌ `/getUsers`  
- ✅ `/users` (HTTP GET)

---

## 2. Используйте HTTP-методы для операций
- **GET** — получение ресурса.
- **POST** — создание ресурса.
- **PUT** — полное обновление ресурса.
- **PATCH** — частичное обновление.
- **DELETE** — удаление.

**Пример**:  
- `GET /users` — список пользователей.
- `POST /users` — создать пользователя.
- `GET /users/{id}` — получить пользователя по ID.
- `PUT /users/{id}` — обновить данные пользователя.
- `DELETE /users/{id}` — удалить пользователя.

---

## 3. Используйте множественное число для коллекций
- Коллекции: `/users`, `/products`.
- Единичный ресурс: `/users/{id}`.

---

## 4. Версионирование API
Добавьте версию в URL или заголовки.  
**Пример**:  
- URL: `/api/v1/users`.
- Заголовок: `Accept: application/vnd.myapi.v1+json`.

---

## 5. Иерархия ресурсов
Для вложенных сущностей используйте иерархию.  
**Пример**:  
- `GET /users/{userId}/posts` — посты пользователя.

---

## 6. Фильтрация, сортировка, пагинация
Используйте query-параметры:  
- `GET /users?role=admin&sort=name,asc`.
- `GET /users?page=2&limit=10`.

---

## 7. Статус-коды HTTP
- `200 OK` — успешный GET/PUT/PATCH.
- `201 Created` — ресурс создан (POST).
- `204 No Content` — успешное удаление (DELETE).
- `400 Bad Request` — неверный запрос.
- `401 Unauthorized` — требуется аутентификация.
- `403 Forbidden` — доступ запрещён.
- `404 Not Found` — ресурс не существует.
- `500 Internal Server Error` — ошибка сервера.

---

## 8. Формат данных
- Используйте JSON как стандарт.
- Указывайте Content-Type: `application/json`.

---

## 9. Именование в lowercase и через дефис
- ❌ `/Users/{id}/EmailAddress`.
- ✅ `/users/{id}/email-address`.

---

## 10. Идемпотентность
Методы GET, PUT, DELETE должны быть идемпотентными (повторный запрос не меняет результат).

---

## 11. Безопасность
- Используйте HTTPS.
- Валидируйте входные данные.
- Ограничивайте частоту запросов (rate limiting).

---

## 12. Документация
Документируйте эндпоинты с помощью инструментов вроде **Swagger/OpenAPI**.

---

```http
GET /api/v1/users?role=admin
POST /api/v1/users
PUT /api/v1/users/123
DELETE /api/v1/users/123
GET /api/v1/users/123/posts?status=published
